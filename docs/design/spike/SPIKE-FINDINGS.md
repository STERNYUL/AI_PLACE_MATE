## 1. 판정형 어휘 기준 — 사실 3요소로 고정한다 *(부분 해소)*

### 판정

**카피는 `값 · 출처 · 일자` 세 요소로만 쓴다.** 형용사 판정을 금지하는 데서 멈추지 않고, **비교 표현도 시스템이 말하지 않는다.**
"예산보다 저렴하다"가 아니라 **"인당 12,000~15,000원 · 입력한 예산 15,000원"** 처럼 두 값을 나란히 놓고 판단은 읽는 쪽에 남긴다.

```
✗  조용한 편이에요 · 가성비 좋은 곳 · 무난한 선택
✗  예산보다 저렴합니다            ← 판정형 어휘는 없지만 '저렴'이 판정이다
○  인당 12,000~15,000원으로 예산 15,000원 이하이고, 바 6석이 1인 좌석으로 확인됐다.
○  좌석 간격 1.2m · 2026-08-15 · 내부 조사
```

### 근거 — 화면에서 무엇을 봤나

- 카드 3장의 `selectionReason`을 나란히 놓으니, **판정형을 뺀 문장이 오히려 짧고 카드 안에서 먼저 읽혔다.** 금지 목록을 지키는 것이 카피 품질을 떨어뜨리지 않는다.
- 판정형 어휘 grep이 `lib/fixtures/`까지 검사하므로 **자리표시자에 판정형이 섞일 여지가 애초에 없다.** 실제로 fixture 작성 중 사용자 질의 표본 한 건(`"…조용히 먹을 데"`)이 grep에 걸려 고쳤다 — **금지 목록이 코드 리뷰가 아니라 작성 시점에 작동한다.**
- 반대로 **"확인됐다"·"같다"·"넘었다" 같은 서술은 판정이 아니다.** 관측된 사실의 진술이고, 이것까지 빼면 문장이 성립하지 않는다.

### 화면 위치

| 위치 | 무엇 |
| --- | --- |
| `1-1` 근거 완비 카드 3장 | `selectionReason` — 파생 문장 3종 |
| `2-3` 근거생략 | `ruleBasedReason` — AI 문장 실패 시 규칙 기반 기본 문구 |
| `1-2` STALE 띠 | *"90일 임계를 넘었다"* — 경고도 사실 진술이다 |

### 남는 것

- **정본 `WRITING-GUIDE.md`는 `UX-C`(#142) 본작업이다.** 이 판정은 그 문서의 §1이 될 기준이지 문서 자체가 아니다.
- **`EVD-B` 판정형 차단 사전과의 통합**이 남는다. 선정 이유는 파생값이라 저장되지 않으므로(S2-T5), 사전을 갱신하면 과거 문장까지 즉시 반영된다 — 이 구조가 성립하는지는 서버 착수 시점에 확인한다.

## 2. 신선도 경고의 시각 위계 — 3단으로 나눈다

### 판정

| 상태 | 표기 | 토큰 |
| --- | --- | --- |
| 임계 **안** (경과 < 90일) | 카드 **하단** 회색 `N일 경과` 만 | `--color-ink-faint` |
| 임계 **이상** (경과 ≥ 90일) | 카드 **상단 전체 폭 경고 띠** + 하단 경과 표기 유지 | `--color-warn` · `--color-warn-soft` |
| `RECHECK_REQUIRED` | **카드가 아니라 제외 패널** | `--color-halt` |

**색만으로 구분하지 않는다.** 띠에 문구를 함께 둔다 — *"확인 후 90일 경과 · 90일 임계를 넘었다"*.

### 근거 — 화면에서 무엇을 봤나

- **89 / 90 / 91일 세 장을 나란히 놓은 것이 결정적이었다.** 처음에 하단 뱃지 하나로만 표기했더니 **89일과 90일이 구분되지 않았다.** 카드 하단은 시선의 종착점이라 스크롤로 훑을 때 지나친다.
- 상단 띠로 올리자 **카드 제목보다 먼저 읽혔고**, 목록에서 훑어도 걸렸다. 카드 4장 중 2장에만 띠가 있는 상태가 대비를 만든다.
- **하단 경과 표기를 없애지 않은 이유** — 임계 안 카드에도 "12일 경과"가 있어야 사용자가 *"경고가 없다 = 최근 확인됐다"* 를 확인 없이 믿지 않는다. 경고의 부재가 정보가 되려면 부재의 근거가 보여야 한다.
- **경계 포함이 화면에서 그대로 보인다** — 90일 당일 카드에 띠가 있다. `≥` 규약(S2-T1)이 코드·계약·화면에서 같은 값을 낸다.

### 화면 위치

`1-2 STALE — 경고 병기` · 사다리 4장 (12일 / 89일 / 90일 / 91일)
기준 시점 `2026-08-27`을 화면 상단에 고지한다 — 경계 3종은 기준 시점 대비로만 성립하므로, 이 값을 숨기면 화면이 사실을 말하지 않는 것이 된다.

### 파생

**`REQ-NF-011` 경고 표기 누락률 0%의 실질 근거가 이 위계다.** 판정 함수가 하나(`lib/evidence/freshness.ts`)이고 표기 컴포넌트가 하나(`components/freshness-note.tsx`)이므로, 누락은 두 곳 중 한 곳의 버그로만 발생한다.

## 3. 후보 3개 미만 화면 — 요약을 먼저, 제외 사유는 나눠서

### 판정

1. **화면 최상단에 통과·제외 요약을 먼저 놓는다** — `통과 3곳 · 근거 누락 4곳 · 재확인 대기 1곳`.
2. **제외 2사유를 각각 별도 패널로** 아래에 둔다. 합치지 않는다.
3. **사과 문구를 쓰지 않는다.** *"3곳을 채우지 못했습니다"* 가 아니라 **"3은 상한이다 — 통과분만 나온다"** 를 적는다.
4. 제외 패널에는 **어느 항목이 비었는지 항목명**을 적는다 — `확인 주체 없음`.

### 근거 — 화면에서 무엇을 봤나

- **사유를 합치면 사용자가 할 수 있는 일이 갈리지 않는다.** 둘은 성격이 다르다.

  | 사유 | 성격 | 시간이 지나면 |
  | --- | --- | --- |
  | 근거 4항목 결락 | **데이터 문제** — 색인에 없는 것 | 안 바뀐다 |
  | `RECHECK_REQUIRED` | **상태 문제** — 신고 접수 후 재확인 대기 | 곧 풀린다 |

  화면이 이 둘을 같은 문장으로 말하면 *"기다리면 되는가"* 에 답이 없다.
- **사과 문구를 시험해 봤을 때 화면이 오류처럼 읽혔다.** 3곳이 안 되는 것은 게이트가 제대로 작동한 결과다 — 규칙 1을 지킨 성공 경로를 실패로 표기하면, 다음 사람이 "채우도록" 고치고 싶어진다.
- **항목명을 적는 것이 검증을 화면으로 끌어온다.** `MOCK-003`의 항목별 누락 4종이 패널에 `선정 이유 없음` · `근거 속성 없음` · `확인 일자 없음` · `확인 주체 없음` 네 칩으로 그대로 보인다. 구현이 실수로 3개만 검사하면 화면에서 한 칩이 영영 안 나온다.

### 화면 위치

`ResultSummary`(요약 스트립) · `1-3 제외 · 근거 누락` · `1-4 제외 · 재확인 대기`

### 남는 것

- **통과 0곳일 때의 전이**는 열화 `제안없음`으로 내려간다(§4 판정과 이어진다). 0곳 화면을 별도로 그리지 않는다 — 상태가 중복된다.
- 제외 건수가 클 때(예 20곳) 패널이 목록을 다 나열할지 접을지는 `UX-F`(#145).

## 4. 부분 파싱 시 필드 이월 — 이월한다

### 판정

**파싱된 슬롯을 구조화 화면에 그대로 채운다.** 그리고 **옮겼다는 사실을 문구로 명시한다** — *"알아들은 슬롯은 그대로 옮겨 두었다. 나머지만 고르면 된다."*

### 근거 — 화면에서 무엇을 봤나

**이월 안과 미이월 안을 나란히 놓은 것이 판정을 갈랐다.** 두 화면은 전환 고지 문구가 **글자 그대로 같은데도** 다르게 읽혔다.

| | 미이월 | 이월 |
| --- | --- | --- |
| 화면 상태 | 입력 문장은 위에 그대로 보이는데 **아래 슬롯이 전부 `미지정`** | 인원 `1명` · 맥락 `성수` 가 채워져 있고 예산·메뉴만 비어 있음 |
| 어떻게 읽히나 | **"실패했다"** — 방금 쓴 문장이 통째로 버려진 것으로 보인다 | **"일부는 됐다"** — 남은 것만 고르면 되는 상태로 보인다 |
| 다음 행동 | 처음부터 다시 | 두 칸만 |

**§1이 이 화면에 건 판정 질문이 *"전환 고지가 오류로 읽히지 않는가"* 였고, 답이 이월 여부로 갈렸다.** 문구를 고쳐서 해결되는 문제가 아니었다 — 미이월 안에서는 화면 상태 자체가 실패를 말한다.

부수 근거 하나 — **파싱이 부분적으로 성공했다는 것은 이미 관측된 사실**이다. 그것을 버리면 시스템이 아는 것을 화면이 모르는 척하는 것이고, *"판정하지 않고 근거를 준다"* 의 반대 방향이다.

### 화면 위치

`3-3 폴백 전환 고지 — 이월` · `3-3 폴백 전환 고지 — 미이월` (같은 상태의 2안. 상태 수는 3 그대로다)

### 남는 것

- **이월된 값을 사용자가 지웠을 때 재파싱할 것인가** — `UX-B`(#141).
- 파싱 신뢰도가 낮은 슬롯을 이월할 때 표시를 다르게 할지 — 신뢰도 값이 계약에 없다. `SPEC-001` 착수 시 함께 본다.

## 5. 후보 0건 시 조건 완화 제안 — 먼저 내밀지 않는다

### 판정

**안 B를 채택한다.** 시스템은 **무엇이 걸렸는지만 사실로 알리고**, 완화는 사용자가 고른다.

```
✗  안 A  "인당 12,000원 이하로 올리기" · "저녁 조건 빼기"   ← 시스템이 포기할 조건을 고른다
○  안 B  "걸린 조건은 인당 8,000원 이하 하나다. 무엇을 뺄지는 고르는 쪽이 정한다."
```

**다음 행동은 남긴다** — `조건 없이 Top-3 보기`. 완화안을 안 내미는 것이지 막다른 길로 두는 것이 아니다.

### 근거 — 화면에서 무엇을 봤나

- **완화안을 고르는 것 자체가 판정이다.** *"예산을 12,000원으로 올리시죠"* 는 **어느 조건을 포기해도 되는지에 대한 시스템의 의견**이다. 예산이 상한선인 사용자(`C2` 예산 우선 이용자)에게 예산 완화를 먼저 내미는 것은 §1.1 *"판정하지 않고 근거를 준다"* 에 정면으로 걸린다.
- **시스템이 할 수 있는 완화는 이미 끝난 뒤다.** `304` 열화 규칙상 후보 부족이면 *조건 완화 → 모집단 재구성 → 다시 게이트* 를 이미 돌린다. `제안없음`까지 왔다는 것은 **파이프라인 완화로도 0곳**이라는 뜻이고, 여기서 남은 완화는 **사용자가 조건을 포기하는 판단**뿐이다. 그 판단을 시스템이 대신 고르면 층이 어긋난다.
- **화면에서 안 A가 모순으로 읽혔다** — 상태 이름이 `제안없음`인데 화면이 제안 두 줄로 차 있다. 사용자는 그 둘을 후보 제안으로 오독할 여지가 있다.
- 안 B의 위험은 막다른 길이 되는 것인데, **걸린 조건명을 적으면 그 위험이 사라진다.** *"인당 8,000원 이하가 걸렸다"* 를 읽으면 무엇을 만질지는 자명하다. 고르는 행위만 사용자에게 남는다.

### 화면 위치

`2-5 제안없음 — 안 A · 완화안을 먼저 내민다` · `2-5 제안없음 — 안 B · 무엇이 걸렸는지만 알린다`
두 안이 같은 상태의 2안이다. **열화 상태 수는 6 그대로다** — 하네스 grep이 세는 6개 명칭은 변하지 않는다.

### 남는 것

- **조건이 여럿 걸렸을 때** 무엇을 먼저 적을지(하나만? 전부?) — `UX-F`(#145).
- Phase 2 대화방의 `제안없음`(유효 제안 0건)과 이 화면(후보 0곳)이 같은 상태 이름을 쓴다. 카피가 갈리는지는 `UX-G` 시점.

## 6. 구현이 확정한 것 — 판정 밖 부산물

미정 항목은 아니지만, 화면을 만드는 과정에서 결정이 굳은 것들이다. `CLI-C1` 정식 착수의 입력이다.

## 7. 문서와 구현이 갈린 곳 — 고치지 않고 기록만 남긴다

목표문 §6이 *"grill 결정이 이긴다. 결정을 바꾸려면 멈추고 보고한다"* 라고 정했다. 아래 둘은 **결정을 바꾼 것이 아니라 결정의 가드를 따른 결과**다.

### 7.1 `top3.json` 상호를 표본 표기로 뒀다

- **스파이크 문서 §3은 실제 매장 3곳의 공개 정보를 요구한다**(S1-T7).
- 같은 절이 파생 가드를 함께 걸었다 — *"실제 매장명 + 미확인 사실 = 근거 없는 정보 노출이고, 이것이 §8.3 규칙 1이 금지하는 바로 그것이다."*
- **이 세션에는 매장을 조사할 수단이 없었다.** 실제 상호에 확인하지 않은 좌석수·가격을 붙이면 가드에 정면으로 걸리고, `verifiedBy`를 `INTERNAL_SURVEY`(내부 조사)로 적는 순간 **하지 않은 조사를 했다고 적는 것**이 된다.
- 그래서 상호를 `성수 표본식당 가/나/다` 로 두고 나머지 형상(가격 3필드 · 대표 메뉴 · 상황 속성 · 확인 일자·주체)은 실제 데이터와 같은 모양으로 채웠다. **판정형 어휘 grep은 그대로 통과한다** — 자리표시자에 판정형이 없다.
- **잃은 것:** *"어느 항목이 현실에서 비는지"* 가 드러나지 않았다. `IDX-C` 초기 적재 착수 시 실측으로 확인해야 한다.
- **`MOCK-002` 이관 시 이 3건을 실제 조사 데이터로 교체한다.**

### 7.2 후보 항목에 `name` 을 뒀다

- 스파이크 문서 §3 스키마 블록은 후보 키를 **7개**로 적었다 — `id` · `priceRange` · `signatureDish` · `contextAttributes` · `selectionReason` · `verifiedAt` · `verifiedBy`. 매장 표기가 없다.
- SRS §3.1.2가 카드에 요구하는 여섯 항목은 **근거 항목**이지 식별 항목이 아니다. 표기가 없으면 카드가 성립하지 않는다.
- 그래서 `name` 을 **여섯 항목 밖의 식별 필드**로 뒀다. 질의 결과 전체의 속성을 항목에 넣지 않는다는 S2-T4 결정은 그대로 지켜진다.
- **`SPEC-002` 착수 시 이 키의 정식 이름을 확정한다.** 잠정 타입은 `types/draft.ts` 한 파일에 격리돼 있어 교체 범위가 그 파일이다.
