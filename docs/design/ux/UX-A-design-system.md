# UX-A · 디자인 시스템 및 모바일 성능 가이드

> 대상: `UX-001`, `UX-013` · 대응 구현: `CLI-A`, `CLI-E`
> 근거: SRS §3.1.2, §8.3, `REQ-NF-006`, ADR-006(R6)

## 1. 화면 목록

이 문서는 이후 화면이 공통으로 쓰는 토큰, 공통 컴포넌트, 초기 렌더 예산을 정리한다. 적용 범위는 조건 입력, 후보 Top-3, 예약·결제, 상태 화면 및 독립 모바일 웹 진입 화면이다.

| 진입 경로 | 공통 화면 영역 | 적용 규칙 |
| --- | --- | --- |
| 지도 앱 내 탭 | 상단 안전 영역, 본문, 하단 행동 영역 | 호스트 앱의 인셋을 우선 반영한다. 실측 전에는 고정 높이·고정 안전 영역 값을 확정하지 않는다. |
| 독립 모바일 웹 | 상단 안전 영역, 본문, 하단 행동 영역 | 동일 토큰을 사용하며, 브라우저 안전 영역을 적용한다. |
| 후보 결과 | 후보 카드, 근거 블록, 신선도 표기 | 근거 4항목이 모두 배치된 카드만 결과 영역에 둔다. |
| 열화·실패 경로 | 로딩, 폴백, 근거 대기·생략, 유사 메뉴 대체, 제안 없음, 재시도 | 어느 경로에도 비어 있는 본문만 남기지 않는다. 상세 상태는 `UX-F`가 확정한다. |

`UX-001`의 시각 설계 범위는 SRS 직접 요구사항이 아니다. 따라서 토큰과 공통 컴포넌트의 제품 적용은 **(미정 — 확정 필요) PM 승인** 후 진행한다. 이 문서는 `UX-013`의 성능 가이드와 후속 태스크의 참조 기준으로 남긴다.

## 2. 상태

모든 공통 상태는 제목, 현재 사실 또는 처리 상태, 다음 행동 또는 유지 중인 콘텐츠를 함께 둔다. 결과 영역은 로딩이나 실패를 이유로 제거하지 않는다.

| 상태 | 공통 표현 | 유지하는 정보 | 다음 처리 |
| --- | --- | --- | --- |
| 초기 로딩 | 골격 카드와 고정된 영역 높이 | 입력 조건 또는 이전 결과 | 데이터 도착 시 결과로 교체 |
| 후보 결과 | 카드 묶음과 근거 블록 | 선정 이유, 근거 속성, 확인 일자, 확인 주체 | 후보 선택 또는 조건 수정 |
| 근거 대기 | 카드 골격과 사실 값 | 확인된 속성·일자·주체 | 근거 문장 도착을 대기 |
| 근거 생략 | 문장 자리 없이 속성·일자·주체 | 확인된 사실 값 | 조건 수정 또는 다시 조회 |
| 폴백 | 구조화 필터와 전환 고지 | 이미 인식된 조건과 기존 결과 | 필터를 조정해 조회 |
| 재시도 | 실패 사유와 재시도 제어 | 마지막으로 표시된 결과 또는 입력 | 동일 요청을 다시 실행 |

후보 카드는 다음 네 슬롯을 분리된 행 또는 의미상 구분되는 블록으로 항상 확보한다. 하나라도 없으면 카드 자체를 결과로 표시하지 않으며, 제외 사실과 이후 가능한 행동을 포함한 상태 화면으로 전환한다.

| 슬롯 | 표시 원칙 |
| --- | --- |
| 선정 이유 | 확인된 속성을 참조한 문장만 둔다. |
| 근거 속성 | 원천 값과 단위를 함께 둔다. |
| 확인 일자 | 날짜를 생략하지 않는다. |
| 확인 주체 | 확인 주체를 생략하지 않는다. |

## 3. 카피

공통 카피는 관찰·확인된 값, 출처, 날짜를 중심으로 쓴다. 다음 문구는 화면에서 사용할 수 있는 형태이며, 값은 실제 응답으로 교체한다.

| 사용 맥락 | 화면 카피 |
| --- | --- |
| 근거 속성 | `좌석 간격 1.2m · 2026-07-15 · 매장 확인` |
| 확인 일자 | `확인 일자 2026-07-15` |
| 확인 주체 | `확인 주체 매장` |
| 신선도 표기 | `확인 일자에서 90일 경과` |
| 폴백 전환 | `입력한 조건을 항목으로 표시했습니다. 필요한 항목을 선택해 계속할 수 있습니다.` |
| 근거 대기 | `확인된 속성을 표시하고 있습니다. 선정 이유를 불러오는 중입니다.` |
| 근거 생략 | `선정 이유를 표시하지 못했습니다. 확인된 속성과 확인 정보는 아래에 있습니다.` |
| 재시도 | `요청을 처리하지 못했습니다. 다시 시도할 수 있습니다.` |

카피는 결과의 순위·품질·적합성을 평가하지 않는다. 정렬 순서를 근거 없이 강조하거나, 확인되지 않은 정보를 보완하는 문구를 추가하지 않는다. 금지 어휘의 정본은 `WRITING-GUIDE.md`이며 `UX-C` 확정 전에는 이 문서의 사실 서술 형식을 임시 기준으로 사용한다.

## 4. 컴포넌트

구현은 shadcn/ui의 `Card`, `Badge`, `Button`, `Input`, `Skeleton`, `Alert`, `Tooltip` 조합을 우선 사용한다. 색상·간격·타이포·반경·그림자는 shadcn 테마 변수와 `tailwind.config.ts` 토큰으로만 지정한다. 컴포넌트 내부의 색상 코드, 임의 픽셀 간격, 화면별 CSS 파일은 추가하지 않는다.

| 컴포넌트 | 구성 | 불변 조건 |
| --- | --- | --- |
| `AppShell` | 상단 안전 영역, 스크롤 본문, 하단 행동 영역 | 지도 앱 내 탭과 독립 웹에서 같은 구조를 사용한다. |
| `CandidateCard` | 매장 식별, 근거 4항목, 신선도 표기, 행동 영역 | 네 근거 슬롯이 모두 없으면 렌더하지 않는다. |
| `EvidenceBlock` | 선정 이유, 속성, 일자, 주체 | 각 항목의 레이블과 값이 함께 보인다. |
| `StatusPanel` | 상태 제목, 사실 또는 처리 상태, 다음 행동 | 빈 본문만 표시하지 않는다. |
| `FreshnessBadge` | 확인 일자 및 90일 경과 표기 | 경과 사실을 카드 본문과 분리해 보인다. |
| `FallbackFilter` | 인식된 조건, 직접 선택 필터, 전환 고지 | 입력값을 지우지 않고 조정 경로를 둔다. |

접근성 기준은 **(미정 — 확정 필요)** 이다. 확정 전 구현은 의미 있는 HTML 구조, 보이는 레이블, 키보드로 도달 가능한 제어, 상태 변경의 텍스트 표현을 기본선으로 유지하고, 목표 WCAG 수준·명도 대비 수치·보조기기 시험 범위는 PM과 접근성 담당자가 확정한다.

## 5. 근거

| 요구 또는 제약 | 설계 반영 |
| --- | --- |
| §8.3 규칙 1 · `REQ-FUNC-010`, `REQ-FUNC-014` | `CandidateCard`와 `EvidenceBlock`에 선정 이유·근거 속성·확인 일자·확인 주체 슬롯을 고정한다. 근거 검증은 적합도 정렬보다 앞선다. |
| §8.3 규칙 5 · `REQ-FUNC-009`, `REQ-NF-009` | 로딩·폴백·근거 대기·근거 생략·재시도에 내용과 행동을 둬 결과 영역이 사라지지 않게 한다. |
| §8.3 규칙 3 | 카피를 사실 값·출처·날짜 형식으로 제한하고, `UX-C`의 라이팅 기준을 참조한다. |
| `REQ-NF-006` | 모바일 4G LCP를 2.5초 이하로 둔다. 아래 초기 렌더 예산을 설계 검토와 구현 검증에 함께 사용한다. |
| ADR-006 · R6 | 지도 앱 내 탭은 자사 통제 밖이므로 실측 전 인셋·뷰포트를 고정하지 않고 독립 모바일 웹 경로를 병행한다. |

초기 렌더 예산은 LCP 2.5초 한도 안에서 합산 관리한다. 카드의 LCP 요소는 텍스트와 CSS로 먼저 표시하며, 필수 이미지가 있을 때만 아래 이미지 예산을 쓴다.

| 예산 항목 | 상한 | 검증 책임 |
| --- | ---: | --- |
| 모바일 4G LCP | 2.5초 | `CLI-E` |
| LCP 요소용 이미지 전송량 | 80 KB | `CLI-A` 구현, `CLI-E` 측정 |
| 첫 화면 이미지 총 전송량 | 120 KB | `CLI-A` 구현, `CLI-E` 측정 |
| 첫 화면 웹폰트 파일 수 | 2개 | `CLI-A` 구현 |
| 첫 화면 웹폰트 총 전송량 | 100 KB | `CLI-A` 구현, `CLI-E` 측정 |
| 초기 화면의 비필수 이미지 | 지연 로드 | `CLI-A` 구현 |
| 초기 화면의 상태 골격 | 고정 높이 사용 | `CLI-A` 구현 |

지도 앱 내 탭의 실제 뷰포트, 상단·하단 안전 영역, 키보드 노출 시 가시 영역은 **(미정 — 확정 필요)** 이며, 지도 플랫폼 환경에서 실측한 뒤 `AppShell` 토큰에 반영한다. 확정 담당자는 PM과 클라이언트 담당자다.

## 6. CLI 인계

| 수신 태스크 | 인계 내용 | 확인 기준 |
| --- | --- | --- |
| `CLI-A` | `AppShell`, 토큰 기반 공통 컴포넌트, `CandidateCard`의 근거 4항목 슬롯, `StatusPanel`의 비어 있지 않은 상태 구조를 구현한다. | 네 슬롯 중 하나라도 누락된 후보는 카드로 렌더되지 않으며, 각 상태에 텍스트와 행동 또는 유지 콘텐츠가 있다. |
| `CLI-A` | shadcn/ui 및 테마 토큰만 사용하고 컴포넌트 내부 하드코딩 색상·간격을 두지 않는다. | 코드 검토에서 임의 CSS 파일과 컴포넌트별 색상·간격 값이 없다. |
| `CLI-A` | 지도 앱 내 탭 실측값이 확정되기 전에는 인셋을 상수로 고정하지 않고, 독립 모바일 웹 경로도 같은 셸을 사용한다. | **(미정 — 확정 필요)** 실측값을 반영하는 변경은 PM·클라이언트 담당자 확인 후 수행한다. |
| `CLI-E` | 모바일 4G에서 LCP 2.5초 이하와 이미지·폰트 예산을 측정한다. | LCP, LCP 이미지, 첫 화면 이미지, 웹폰트 수·전송량을 같은 측정 보고서에 남긴다. |
| `CLI-E` | 지도 앱 내 탭과 독립 모바일 웹의 뷰포트·안전 영역을 실측한다. | 실측 환경, 뷰포트, 상·하단 인셋, 키보드 노출 시 가시 영역을 기록한다. |

미정 항목의 확정 전에는 임의의 접근성 등급·색 대비 기준·지도 앱 내 탭 치수를 추가하지 않는다. `UX-001` PM 승인 기록, 접근성 기준, 지도 앱 내 탭 실측 결과가 갖춰지면 이 문서를 갱신해 구현 기준으로 확정한다.
