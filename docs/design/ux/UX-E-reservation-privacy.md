# UX-E — 예약·결제·취소 및 개인 제약 동의

> 대상: `UX-008`, `UX-012` · 대응 구현: `CLI-D`, `PRV-B`
> 근거: `REQ-FUNC-015`~`017`, `REQ-NF-014`, `REQ-NF-032`, SRS §8.6.4

## 1. 화면 목록

| 진입 경로 | 화면 | 이용자에게 보이는 내용 |
| --- | --- | --- |
| 후보 카드의 예약 행동 | 예약 확인 | 매장명, 이미 선택된 일시·인원·메뉴 조건, 결제 수단 요약, 취소 시한 |
| 예약 확인의 결제 진행 | 결제 진행 | 전달되는 예약 값, 결제 처리 상태, 이전 화면으로 돌아가기 |
| 개인 제약 사용이 필요한 예약 | 개인 제약 동의 | 단말 보관 범위, 서버 전송 범위, 미동의 경로, 철회 경로 |
| 예약 완료 후 예약 조회 | 예약 상세·취소 | 예약 사실, 취소 시한, 취소 결과 또는 다음 행동 |
| 결제·예약 처리 실패 또는 중단 | 처리 상태 | 직전 예약 값과 실패 사유, 재시도 또는 예약 목록으로 가는 행동 |

예약 흐름은 후보 카드에서 이미 확보한 값만 사용한다. 이용자가 예약·결제·취소 과정에서 다시 입력하는 필드는 0개다. 누락된 예약 값이 있으면 입력 화면을 새로 열지 않고 후보 카드의 조건 수정 경로를 표시한다.

## 2. 상태

| 상태 | 표시 내용 | 다음 행동 |
| --- | --- | --- |
| 예약 확인 | 매장명, 선택된 조건, 결제 수단 요약, 행동 전 취소 시한 | 결제 진행 또는 후보 조건 수정 |
| 결제 진행 | 예약 값과 결제 처리 중임을 알리는 상태 패널 | 처리 완료 대기 또는 이전 화면으로 돌아가기 |
| 동의 요청 | 개인 제약의 단말 보관 항목, 서버 전송 항목, 미동의 진행 행동 | 동의 후 진행 또는 전송 없이 진행 |
| 미동의 진행 | 개인 제약을 서버로 보내지 않았다는 사실과 가능한 예약 범위 | 예약 확인으로 계속 |
| 동의 철회 | 철회 후 서버 전송을 중단한다는 사실과 단말 항목 처리 범위 | 철회 확정 또는 이전 상태 유지 |
| 취소 전 확인 | 취소 시한, 환불 가능 여부, 취소 대상 예약 사실 | 취소 실행 또는 예약 상세로 돌아가기 |
| 처리 중단·실패 | 마지막 예약 값, 처리되지 않은 단계, 사유, 재시도 행동 | 같은 요청 재시도 또는 예약 목록으로 이동 |
| 취소 완료 | 취소 처리 시각과 환불 처리 상태 | 예약 목록으로 이동 |

어느 상태도 본문을 비워 두지 않는다. 결제 또는 예약 처리 결과가 아직 없을 때에도 예약 값, 현재 단계, 다음 행동을 함께 표시한다.

## 3. 카피

| 사용 맥락 | 화면 카피 |
| --- | --- |
| 예약 확인 | `선택한 조건으로 예약을 진행합니다. 아래 내용은 후보 카드에서 선택한 값입니다.` |
| 재입력 없음 | `이 단계에서 새로 입력할 항목은 없습니다. 조건을 바꾸려면 후보 카드로 돌아가세요.` |
| 취소 시한 | `취소 시한: (미정 — 확정 필요: RSV-D가 정한 경계와 환불 처리 기준)` |
| 결제 진행 | `결제와 예약 요청을 처리하고 있습니다. 처리 결과가 나오기 전에도 선택한 조건을 확인할 수 있습니다.` |
| 단말 기본 보관 | `개인 제약은 이 기기에 기본 보관합니다.` |
| 서버 전송 동의 | `동의하면 아래 개인 제약 항목을 예약 처리 목적에 한해 서버로 전송합니다: [실제 전송 항목].` |
| 미동의 경로 | `동의하지 않아도 개인 제약을 서버로 보내지 않고 예약을 계속할 수 있습니다. 전송이 필요한 기능은 사용할 수 없습니다.` |
| 보존 기간 | `서버 전송 정보의 보존 기간: (미정 — 확정 필요: 법무·PRV-A 확인)` |
| 철회 | `동의를 철회하면 이후 예약 요청에서 개인 제약을 서버로 보내지 않습니다.` |
| 취소 전 확인 | `취소를 실행하기 전에 취소 시한과 환불 처리 기준을 확인하세요.` |
| 처리 실패 | `요청을 처리하지 못했습니다. 마지막으로 선택한 예약 조건을 확인한 뒤 다시 시도할 수 있습니다.` |

`[실제 전송 항목]`은 `PRV-B`가 확정한 전송 범위만 표시한다. 화면은 순위, 품질, 선호도에 관한 평가 문구를 생성하지 않는다.

## 4. 컴포넌트

| 컴포넌트 | 구성 | 적용 조건 |
| --- | --- | --- |
| `ReservationSummaryCard` | 매장명, 선택 조건, 결제 수단 요약, 취소 시한 | 후보 카드의 선택 값을 읽기 전용으로 표시한다. 입력 필드를 두지 않는다. |
| `CancellationDeadline` | 취소 시한, 환불 처리 기준, 기준 확인 상태 | 행동 버튼보다 앞에 놓고 `RSV-D` 확정 값을 사용한다. |
| `ConsentScopeCard` | 단말 보관 항목, 서버 전송 항목, 보존 기간, 철회 경로 | 전송 동의가 필요한 경우에만 표시하며 미동의 행동을 같은 화면에 둔다. |
| `ConsentActions` | 동의 후 진행, 전송 없이 진행, 철회 확정 | 미동의 또는 철회가 막히지 않도록 독립 행동으로 둔다. |
| `ProcessingStatusPanel` | 현재 단계, 마지막 예약 값, 사유, 재시도 행동 | 결제·예약·취소의 대기와 실패 상태에 표시한다. |
| `CancellationConfirmCard` | 취소 대상, 취소 시한, 환불 처리 기준, 취소 행동 | 취소 행동 이전에 필요한 사실을 함께 표시한다. |

구현은 shadcn/ui의 `Card`, `Badge`, `Button`, `Alert`, `Tooltip`, `Skeleton`을 사용한다. 색상·간격·타이포 값은 UX-A의 토큰과 shadcn 테마 변수로만 정한다.

## 5. 근거

| 요구사항 또는 제약 | 설계 반영 |
| --- | --- |
| `REQ-FUNC-015` | 예약 시작부터 완료까지 이용자 입력 필드를 0개로 두고, 누락값은 후보 조건 수정 경로로 되돌린다. |
| `REQ-FUNC-016`, `REQ-FUNC-017` | 결제 진행, 예약 상세, 취소 전 확인, 취소 완료 상태를 분리해 예약·결제·취소 흐름을 표시한다. |
| `REQ-NF-014` | 개인 제약은 단말에 기본 보관하고, 서버 전송은 명시적 동의 행동 뒤에만 가능하게 한다. |
| `REQ-NF-032` | 동의하지 않아도 전송 없이 예약을 계속하는 경로와, 동의 철회 경로를 화면에 둔다. |
| SRS §8.6.4 | 동의 화면의 전송 항목·목적·보존 기간·철회 경로는 실제 처리와 일치해야 한다. 보존 기간은 `(미정 — 확정 필요: 법무·PRV-A 확인)`으로 남긴다. |
| SRS §8.3 규칙 5 | 처리 중단·실패·대기 상태에도 예약 값, 상태 설명, 다음 행동을 표시해 빈 화면을 만들지 않는다. |

후보 카드에서 예약으로 이어지는 매장 정보는 근거 4항목(선정 이유, 근거 속성, 확인 일자, 확인 주체)을 모두 갖춘 후보만 사용한다. 신선도 경고가 있는 후보도 사실 표시는 유지하며 예약 화면에서 임의 평가를 추가하지 않는다.

## 6. CLI 인계

| 수신 태스크 | 인계 내용 | 확인 기준 |
| --- | --- | --- |
| `CLI-D` | `ReservationSummaryCard`의 읽기 전용 선택 값으로 예약·결제·취소를 연결하고, 전 과정에서 이용자 입력 필드 0개를 유지한다. | 예약 시작·결제·취소 화면의 입력 요소 수가 0이고, 값 누락 시 후보 조건 수정 경로가 보인다. |
| `CLI-D` | `CancellationDeadline`을 취소 실행 전 표시하고 `RSV-D`가 확정한 시한·환불 기준을 사용한다. | 취소 행동 전에 시한과 환불 처리 기준이 표시된다. `(미정 — 확정 필요: RSV-D)`는 확정 전까지 유지한다. |
| `CLI-D` | 결제·예약·취소 대기 또는 실패에 `ProcessingStatusPanel`을 표시한다. | 각 상태에 마지막 예약 값, 사유 또는 처리 단계, 재시도·이동 행동이 있어 본문이 비어 있지 않다. |
| `PRV-B` | 동의 전송 범위, 전송 목적, 단말 보관 범위, 철회 뒤 처리 범위를 확정해 `ConsentScopeCard`에 공급한다. | 동의 카피의 항목과 실제 전송이 일치하고, 미동의 경로에서는 개인 제약 전송이 발생하지 않는다. |
| `PRV-B` | 보존 기간과 철회 처리의 법적 기준을 `PRV-A`·법무와 확인한다. | `(미정 — 확정 필요: 법무·PRV-A 확인)` 표기는 확정된 기간과 담당자로 교체되며, 철회 뒤 전송 중단을 검증한다. |
