# UX-F — 빈 화면 금지 상태 설계

> 대상 `UX-014` · 선행 `UX-B`, `UX-C` · 구현 인계 `CLI-A`, `CLI-B`, `CLI-C`
> 근거: SRS §3.1.2, §4.5.3, §8.3 규칙 1·3·5, `REQ-FUNC-025`

## 1. 화면 목록

이 문서는 조건 입력과 Top-3 결과에 공통으로 붙는 열화 상태를 정한다. 각 상태는 상태 문구만 남기지 않고, 현재 남아 있는 사실 값 또는 결과 영역과 다음 행동을 함께 보인다. 후보 카드는 선정 이유·근거 속성·확인 일자·확인 주체가 모두 있는 경우에만 표시한다. 누락 후보는 정렬 전에 제외하며, 제외 수와 제외 사유는 결과 영역에 남긴다.

| 진입 경로 | 화면 | 유지하는 내용 | 다음 행동 |
| --- | --- | --- | --- |
| 조건 해석 실패 또는 시한 초과 | 구조화 필터 전환 | 원문, 해석된 항목, 이전 Top-3 | 항목을 직접 선택해 조회 |
| 근거 문장 수신 지연 또는 실패 | 결과 상태 패널 | 카드의 확인된 사실 값, 확인 일자, 확인 주체 | 문장 수신 대기 또는 조건 수정 |
| 메뉴 색인 미등재 | 대체 표시 결과 | 원래 메뉴, 대체 메뉴, 확인된 후보 | 메뉴 선택 변경 또는 조회 |
| 대화방 유효 제안 0건 | Top-3 회귀 | 현재 조건의 Top-3와 제안 수 | 후보를 열어 보기 |
| DB 또는 PG 처리 실패 | 재시도 상태 | 마지막으로 확인된 조건 또는 결과 영역 | 같은 요청 재시도 또는 조건 수정 |

후보가 0건인 경우에도 결과 영역을 제거하지 않는다. 조건 완화 제안을 제공할지와 그 항목 범위는 **(미정 — 확정 필요)** `SRC-B` 담당자와 PM이 결정한다. 근거 미비 후보의 제외 사유를 어떤 문구로 분류해 표시할지도 **(미정 — 확정 필요)** `SRC-D` 담당자와 PM이 결정한다. 확정 전에는 추정한 조건을 채우거나 누락 근거를 보완한 카드로 바꾸지 않는다.

## 2. 상태

| 상태 | 진입 조건 | 화면에 남기는 사실과 구조 | 다음 행동 |
| --- | --- | --- | --- |
| 폴백표시 | AI 조건 해석 실패 또는 제한 시간 도달 | `FallbackFilter`, 원문, 해석 완료 항목, 직접 선택 항목, 이전 Top-3 또는 결과 골격, 전환 사실 | 항목을 직접 선택한 뒤 조회한다. |
| 근거대기 | 후보의 근거 문장 스트림이 아직 끝나지 않음 | `CandidateCard` 골격, 근거 속성, 확인 일자, 확인 주체, 문장 자리의 `Skeleton` | 문장 수신을 기다리거나 조건 입력으로 돌아간다. |
| 근거생략 | 근거 문장 스트림 실패 | 근거 속성, 확인 일자, 확인 주체와 문장 미표시 사유; 선정 이유가 없는 후보 카드는 표시하지 않는다 | 조건을 수정하거나 다시 조회한다. |
| 유사메뉴대체 | 요청 메뉴가 색인에 없고 대체 메뉴가 확인됨 | 요청 메뉴명, 대체 메뉴명, 대체 발생 사실, 대체 메뉴 기준의 근거 4항목을 갖춘 후보 | 메뉴 항목을 변경하거나 현재 대체 기준으로 조회한다. |
| 제안없음 | Phase 2 대화방에서 유효 제안이 0건 | 제안 수 `0건`, 현재 조건, 근거 4항목을 갖춘 Top-3 결과 | Top-3로 회귀하여 후보를 연다. |
| 재시도안내 | DB 조회 또는 PG 처리 실패 | 처리하지 못한 요청 종류, 마지막 조건 또는 마지막 Top-3, 재시도 제어 | 같은 요청을 다시 실행하거나 조건을 수정한다. |

`근거대기`는 근거 속성·확인 일자·확인 주체가 이미 검증된 카드에만 적용한다. `근거생략`은 선정 이유가 누락된 후보를 예외로 보이게 하는 상태가 아니다. 근거 4항목 중 하나라도 없는 후보는 `EvidenceGate`에서 제외되고, 상태 영역에는 제외 수와 분류된 사유만 남긴다. 이 사유의 분류 문구는 **(미정 — 확정 필요)** 이다.

## 3. 카피

상태 카피는 처리 사실과 사용자가 실행할 수 있는 행동만 말한다. 수치·일자·속성은 실제 응답 값으로 치환하며, 확인되지 않은 값은 문장으로 만들지 않는다.

| 사용 맥락 | 화면 카피 |
| --- | --- |
| 구조화 필터 전환 | `입력한 조건을 항목으로 표시했습니다. 필요한 항목을 직접 선택해 계속할 수 있습니다.` |
| 근거 문장 수신 중 | `근거 속성과 확인 정보를 표시했습니다. 선정 이유 문장을 불러오는 중입니다.` |
| 근거 문장 미표시 | `선정 이유 문장을 표시하지 못했습니다. 근거 속성과 확인 정보는 아래에 있습니다.` |
| 색인 미등재 메뉴 | `요청 메뉴는 색인에 없습니다. {대체 메뉴명} 기준으로 표시했습니다.` |
| 유효 제안 수 0건 | `유효 제안 0건입니다. 현재 조건의 Top-3를 표시합니다.` |
| 처리 실패 | `{요청 종류}을 처리하지 못했습니다. 다시 시도하거나 조건을 수정할 수 있습니다.` |
| 근거 미비 제외 | `근거 항목 누락으로 제외된 후보 {n}건` |
| 후보 0건 | `조건에 맞는 후보를 표시하지 못했습니다. 조건을 수정하거나 다시 조회할 수 있습니다.` |

후보 0건에서 조건 완화 행동을 노출할지 여부와 카피는 **(미정 — 확정 필요)** 이다. 확정 담당자는 `SRC-B` 담당자와 PM이다. 모든 상태에서 이전 Top-3, 결과 골격, 조건 요약 중 하나 이상을 남겨 상태 문구만 보이는 본문이 생기지 않게 한다.

## 4. 컴포넌트

구현은 `UX-A`의 토큰과 shadcn/ui `Card`, `Alert`, `Badge`, `Button`, `Skeleton`, `Tooltip`을 조합한다. 화면별 CSS, 색상 코드, 간격 값은 추가하지 않는다.

| 컴포넌트 | 구성 | 사용 조건 |
| --- | --- | --- |
| `StatusPanel` | 상태 제목, 사실 값, 다음 행동 | 여섯 상태 모두에서 본문과 함께 사용 |
| `FallbackFilter` | 원문, 해석 항목, 직접 선택 필드, 전환 고지 | `폴백표시` |
| `CandidateCard` | 매장 식별, `EvidenceBlock`, `FreshnessBadge`, 행동 영역 | 근거 4항목이 모두 검증된 후보만 |
| `EvidenceBlock` | 선정 이유, 근거 속성, 확인 일자, 확인 주체 | 후보 카드와 대체 메뉴 후보에 사용 |
| `CandidateCountPanel` | 통과 후보 수, 제외 수, 조건 수정·재조회 행동 | 후보 0~2건 또는 근거 미비 제외 발생 |
| `ProposalFallbackPanel` | 제안 수, 현재 조건 Top-3 진입 제어 | `제안없음` |
| `RetryPanel` | 요청 종류, 마지막 조건 또는 결과, 재시도 제어 | `재시도안내` |

`StatusPanel`은 상태 자체만 표시하지 않고 위 표의 유지 내용과 행동을 자식 영역으로 받는다. `CandidateCard`는 카드 내부에서 근거를 조립하거나 후보 순서를 계산하지 않는다. 상태 전환과 근거 검증은 서버 경계에서 끝낸 뒤 표시용 상태와 검증된 결과만 전달한다.

## 5. 근거

| 요구사항 또는 제약 | 설계 반영 |
| --- | --- |
| SRS §8.3 규칙 5 | 여섯 상태 모두 사실 값 또는 결과 구조와 다음 행동을 정의했다. |
| SRS §8.3 규칙 1, `REQ-FUNC-010`, `REQ-FUNC-014` | 근거 4항목 누락 후보는 정렬 전에 제외하고 카드로 표시하지 않는다. |
| SRS §8.3 규칙 3 | 카피는 처리 사실, 수치, 속성, 확인 정보, 다음 행동만 사용한다. |
| SRS §4.5.3, `REQ-FUNC-009` | 해석 실패는 오류 본문이 아니라 구조화 필터 전환으로 이어진다. |
| `REQ-FUNC-025` | Phase 2 제안이 0건이면 제안 화면을 비우지 않고 현재 조건의 Top-3로 회귀한다. |
| UX-B | `폴백표시`는 원문과 해석된 항목을 보존한 `FallbackFilter`를 사용한다. |
| UX-C | 후보·대체 후보는 근거 게이트 통과 후에만 표시하며, 신선도 표시는 후보 제외 사유가 아니다. |

Phase 2가 미도입이어도 Phase 1의 상태 설계와 구현은 대기하지 않는다. `제안없음`은 Phase 2가 활성화된 경우에만 진입하고, 그 전에는 Top-3 결과 흐름이 그대로 유지된다.

## 6. CLI 인계

| 수신 태스크 | 인계 내용 | 확인 기준 |
| --- | --- | --- |
| `CLI-A` | `StatusPanel`, `RetryPanel`, 결과 골격을 앱 셸의 공통 상태로 구현한다. | 여섯 상태에서 상태 문구만 있는 본문이 없고, 토큰과 shadcn 컴포넌트만 사용한다. |
| `CLI-B` | AI 해석 실패·시한 초과를 `FallbackFilter`로 전환하고 원문·해석 항목·직접 선택 항목을 보존한다. | 전환 후 직접 선택과 재조회 행동이 보이며 이전 Top-3 또는 결과 골격이 남는다. |
| `CLI-C` | `EvidenceGate` 뒤의 후보 결과, 근거대기·근거생략, 유사메뉴대체, 후보 수·제외 수 표시를 구현한다. | 근거 4항목 누락 후보가 카드 및 정렬 입력에 없고, `STALE` 후보는 표시되며, 제외 사유와 다음 행동이 보인다. |

`CLI-B`는 후보 0건의 조건 완화 행동을 구현하기 전에 **(미정 — 확정 필요)** `SRC-B` 담당자와 PM의 결정을 반영한다. `CLI-C`는 근거 미비 제외 사유의 분류·노출 방식을 구현하기 전에 **(미정 — 확정 필요)** `SRC-D` 담당자와 PM의 결정을 반영한다.
