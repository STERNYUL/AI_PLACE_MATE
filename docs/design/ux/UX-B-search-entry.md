# UX-B · 조건 입력 및 폴백 필터

> 대상: `UX-002`, `UX-003` · 선행: `UX-A` · 대응 구현: `CLI-B`
> 근거: SRS §3.1.2, §4.5.3, §8.3, `REQ-FUNC-008`, `REQ-FUNC-009`, ADR-006(R6)

## 1. 화면 목록

조건 입력은 자연어 입력, 인식 결과 확인·수정, 직접 선택 필터를 하나의 연속 흐름으로 둔다. 자연어 해석이 끝나지 않거나 직접 선택으로 바뀌어도 사용자가 적은 원문과 이미 인식된 값은 유지한다. 지도 앱 내 탭에서는 키보드가 입력 영역과 다음 행동을 가리지 않도록 입력 영역을 스크롤 가능한 본문에 두고, 하단 행동 영역은 현재 초점과 겹치지 않게 처리한다. 실제 인셋과 키보드 가시 영역은 **(미정 — 확정 필요)** 지도 플랫폼 실측 후 `CLI-B`가 `CLI-A`의 셸 기준에 맞춰 반영한다.

| 진입 경로 | 화면 | 사용자에게 보이는 내용 | 다음 행동 |
| --- | --- | --- | --- |
| 첫 진입 | 자연어 조건 입력 | 입력 레이블, 예시, 이전에 입력한 원문 또는 빈 입력칸 | 조건 입력 후 `조건 확인` 선택 |
| 해석 완료 | 인식 조건 확인·수정 | 원문, 인식한 항목과 각 값, 비어 있는 항목의 표시 | 각 항목 수정 또는 `후보 보기` 선택 |
| 직접 선택 전환 | 폴백 필터 | 전환 고지, 원문, 인식한 값, 직접 선택 항목 | 항목 선택 후 `후보 보기` 선택 |
| 이전 결과가 있는 재진입 | 조건 수정 | 이전 Top-3와 마지막 조건 | 조건을 수정하거나 같은 조건으로 다시 조회 |

입력 예시는 조건의 종류를 보여 주기 위한 것이며, 예시를 선택해도 예시에 없는 조건을 자동으로 보태지 않는다. 예시: `합정에서 2명, 1인 2만원 이하, 유아 의자 있는 곳`.

## 2. 상태

각 상태는 입력 또는 이전 결과를 유지하고, 상태만 남은 빈 본문을 만들지 않는다. 후보 결과를 함께 보일 때에는 근거 4항목이 갖춰진 카드만 유지하며, 카드의 근거 규격은 `UX-C`를 따른다.

| 상태 | 화면 표현 | 유지 콘텐츠 | 다음 행동 |
| --- | --- | --- | --- |
| 입력 전 | 입력칸, 조건 예시, 이전 조건이 있으면 원문 | 이전 원문과 이전 Top-3 | 자연어 입력 또는 예시 선택 |
| 해석 중 | 입력칸과 원문, 인식 영역의 골격 | 원문, 이전에 확정한 조건, 이전 Top-3 | 해석 완료를 기다리거나 입력 수정 |
| 해석 완료 | 인식된 항목을 레이블·값 쌍으로 표시 | 원문, 인식한 항목, 값이 없는 항목 | 항목 수정 또는 후보 조회 |
| 해석 실패 후 폴백 | 직접 선택 필터와 전환 고지 | 원문, 이전 Top-3, 해석 전에 확정한 조건 | 필터 항목을 직접 선택 |
| 부분 해석 | 원문과 인식한 항목, 직접 선택 진입 제어 | 원문, 인식한 항목, 이전 Top-3 | 인식 항목 확인 후 나머지 항목 선택 |
| 조회 중 | 확정 조건 요약과 후보 영역 골격 | 확정 조건, 이전 Top-3 또는 결과 영역 골격 | 조회 완료 대기 또는 조건 수정 |
| 조회 재시도 | 처리 사유와 재시도 제어 | 마지막 확정 조건, 마지막 Top-3 또는 필터 | 같은 조건으로 다시 조회 또는 조건 수정 |

부분 해석에서 인식한 조건을 직접 선택 필드로 이월하는 방식, 인식하지 못한 조건의 표시 방식, 사용자가 이월 값을 지우는 방식은 **(미정 — 확정 필요)** 이다. `CLI-B`는 이 항목을 API 응답 계약과 함께 확정하며, 확정 전에는 인식하지 못한 조건을 기본값으로 채우지 않는다.

## 3. 카피

카피는 입력·인식·선택이라는 처리 사실과 다음 행동만 말한다. 결과 수, 순위, 장소의 품질을 평가하는 표현을 넣지 않는다. 값과 날짜가 필요한 결과 카피는 실제 응답의 사실 값으로 교체한다.

| 사용 맥락 | 화면 카피 |
| --- | --- |
| 입력 레이블 | `원하는 조건을 적어 주세요` |
| 입력 안내 | `인원, 지역, 메뉴, 시간, 예산처럼 필요한 조건을 적을 수 있습니다.` |
| 해석 중 | `입력한 조건을 항목으로 정리하고 있습니다.` |
| 해석 완료 | `아래 항목을 확인하고 필요한 값을 바꿀 수 있습니다.` |
| 값 미입력 항목 | `선택한 값 없음` |
| 폴백 전환 고지 | `입력한 조건을 항목으로 표시했습니다. 필요한 항목을 직접 선택해 계속할 수 있습니다.` |
| 부분 해석 | `인식한 항목을 표시했습니다. 필요한 항목을 직접 선택해 추가할 수 있습니다.` |
| 조회 중 | `선택한 조건으로 후보를 불러오고 있습니다.` |
| 재시도 | `요청을 처리하지 못했습니다. 같은 조건으로 다시 시도하거나 조건을 바꿀 수 있습니다.` |

전환 고지는 오류나 사용자 입력의 잘못을 말하지 않는다. 직접 선택 전환은 자연어 입력 흐름 안의 정상 분기이며, 원문은 편집 가능한 상태로 남긴다.

## 4. 컴포넌트

구현은 `UX-A`의 shadcn/ui 및 토큰 원칙을 따른다. 새 화면별 CSS 파일, 색상 코드, 임의 간격 값은 추가하지 않는다.

| 컴포넌트 | 구성 | 불변 조건 |
| --- | --- | --- |
| `ConditionForm` | 자연어 입력, 예시, 제출 제어 | 원문을 제출·전환 뒤에도 보존한다. |
| `ParsedConditionList` | 인식 항목의 레이블, 값, 수정 제어 | 사용자가 말하지 않은 항목을 값이 있는 항목으로 만들지 않는다. |
| `ConditionField` | 직접 선택 항목, 선택값, 비어 있음 표기 | 값이 없으면 그 사실을 보이고 임의 기본값을 넣지 않는다. |
| `FallbackFilter` | 전환 고지, 인식된 값, 직접 선택 필드 | 폴백을 오류 화면으로 대체하지 않고 원문과 다음 행동을 둔다. |
| `StatusPanel` | 처리 상태, 유지 콘텐츠, 다음 행동 | 어떤 상태에도 상태 문구만 남기지 않는다. |
| `CandidateSummary` | 이전 Top-3 또는 결과 영역 골격 | 후보 카드가 있을 때는 근거 4항목이 있는 카드만 표시한다. |

`ConditionForm`은 상태와 입력이 필요한 클라이언트 컴포넌트가 될 수 있다. 그 밖의 결과와 근거 표시는 `UX-A`의 Server Component 기본 원칙을 유지한다. 접근성 목표 수준과 지도 앱 내 탭 실측값은 **(미정 — 확정 필요)** 이며, 확정 전에도 보이는 레이블, 키보드 도달 가능한 제어, 상태 변화의 텍스트 표현을 유지한다.

## 5. 근거

| 요구 또는 제약 | 설계 반영 |
| --- | --- |
| `REQ-FUNC-008` | 자연어 조건 입력, 입력 예시, 해석 결과의 확인·수정 경로를 한 흐름으로 둔다. |
| `REQ-FUNC-009` | 직접 선택 전환 때 전환 사실과 다음 행동을 고지하고, 원문과 인식된 값을 보존한다. |
| SRS §4.5.3 | 해석 실패를 오류 화면으로 분리하지 않고 직접 선택으로 이어지는 정상 분기로 설계한다. |
| SRS §8.3 규칙 3 | 화면 카피를 입력·처리 상태·사실 값 중심으로 한정한다. |
| SRS §8.3 규칙 5 | 입력 전, 해석 중, 폴백, 부분 해석, 조회 중, 재시도에 유지 콘텐츠와 다음 행동을 둔다. |
| SRS §8.3 규칙 1 | 후보를 유지해 보일 경우 근거 4항목이 모두 있는 카드만 둔다. |
| ADR-006(R6) | 지도 앱 내 탭에서 키보드와 안전 영역을 고려하되 고정 치수는 실측 전 확정하지 않는다. |

## 6. CLI 인계

| 수신 태스크 | 인계 내용 | 확인 기준 |
| --- | --- | --- |
| `CLI-B` | 자연어 원문을 입력·해석 완료·직접 선택 전환·재시도 상태에서 보존한다. | 전환 뒤에도 원문을 확인·수정할 수 있다. |
| `CLI-B` | 해석 결과를 레이블·값 쌍으로 표시하고 수정 제어를 제공한다. | 사용자가 말하지 않은 조건이 기본값으로 채워지지 않는다. |
| `CLI-B` | 해석 실패를 `FallbackFilter`로 연결하고 전환 고지를 표시한다. | 오류 어조 없이 직접 선택이라는 다음 행동이 보인다. |
| `CLI-B` | 부분 해석의 값 이월·비인식 항목·값 삭제 규칙을 API 계약과 함께 확정한다. | **(미정 — 확정 필요)** 확정 담당: `CLI-B` 담당자와 API 계약 담당자. 확정 전에는 비인식 조건을 채우지 않는다. |
| `CLI-B` | 입력·처리 상태마다 이전 원문, 이전 Top-3 또는 결과 영역 골격과 다음 행동을 둔다. | 상태 문구만 있는 화면이나 빈 결과 본문이 없다. |
| `CLI-B` | 지도 앱 내 탭의 키보드·안전 영역 실측 후 입력 영역과 다음 행동의 가시 영역을 조정한다. | **(미정 — 확정 필요)** 실측 환경·인셋·키보드 가시 영역을 기록하고 `CLI-A` 셸과 함께 검토한다. |
