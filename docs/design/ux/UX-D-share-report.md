# UX-D · 공유 카드·조건 불일치 신고

> 대상: `UX-006`, `UX-007` · 선행: `UX-C` · 인계: `CLI-C`, `EVD-C`, `EVD-D`
> 근거: SRS §3.1.2, §4.5.3, §8.3 규칙 1·3·5, `REQ-FUNC-012`, `REQ-FUNC-013`

## 1. 화면 목록

공유 카드는 결과의 후보 카드에서 공유 동작을 선택한 뒤 만든다. 공유 대상은 근거 게이트를 통과해 이미 화면에 보인 후보 하나이며, 메신저·SNS와 같은 외부 화면에서 열렸을 때도 카드 안에서 선정 이유, 근거 속성, 확인 일자, 확인 주체를 모두 읽을 수 있어야 한다. 외부 화면에서 원래 결과 화면으로 돌아가야만 확인할 수 있는 필드는 두지 않는다.

| 화면 또는 영역 | 진입 조건 | 화면에 남는 내용 |
| --- | --- | --- |
| 공유 전 확인 | 근거 4항목을 가진 후보에서 공유 선택 | 매장 식별, 근거 4항목, 신선도 표기, 생성 제어 |
| 공유 카드 | `EVD-C` 검증을 통과해 공유용 데이터 생성 완료 | 매장 식별, 근거 4항목, 확인 일자·주체, 원본 열기 경로 |
| 공유 불가 상태 | 근거 4항목 중 하나가 없음 | 누락 필드명, 공유를 만들지 않은 사실, 원본 결과 또는 조건 수정 경로 |
| 조건 불일치 신고 | 공유 카드 또는 원본 후보에서 신고 선택 | 신고 대상 식별, 사유 선택, 사실 입력, 제출 제어 |
| 신고 접수 상태 | `EVD-D`가 접수 식별자를 반환 | 접수 식별자, 제출 시각, 처리 상태, 원본으로 돌아가는 경로 |
| 신고 전송 실패 | 신고 요청이 완료되지 않음 | 전송 실패 사실, 작성 내용 유지, 다시 전송 또는 취소 제어 |

공유 불가 상태는 임시 공유 카드나 누락값 대체 문구를 만들지 않는다. 상태 영역에는 누락된 필드와 다음 행동을 남기므로 빈 화면이 되지 않는다.

## 2. 상태

공유와 신고는 서로 다른 상태로 관리한다. 공유 카드는 `EVD-C`가 근거 4항목을 모두 검증한 경우에만 생성한다. 신고는 제출 이전에도 사유 선택과 입력 내용을 유지하며, 전송 실패가 작성 내용을 지우지 않는다.

| 상태 | 조건 | 카드 또는 상태 영역 | 다음 처리 |
| --- | --- | --- | --- |
| 공유 가능 | 선정 이유·근거 속성·확인 일자·확인 주체가 모두 있음 | 네 항목 전체와 공유 생성 제어 | `EVD-C`에 공유 데이터 요청 |
| 공유 불가 | 네 항목 중 하나 이상 없음 | 누락 필드명, 원본 결과, 조건 수정 제어 | 공유 카드 미생성 |
| 긴 근거 | 근거 문장이 카드 영역보다 길어짐 | 전체 문장, 근거 속성, 일자, 주체 | 줄임표·접기·생략 없이 원문 전체 표시 |
| 신고 작성 | 후보 또는 공유 카드에서 신고 진입 | 대상 매장 식별, 사유 선택, 사실 입력, 제출 제어 | 입력 검증 후 제출 |
| 신고 접수 | `EVD-D`가 접수 완료를 반환 | 접수 식별자, 제출 시각, 처리 상태 | 원본 결과 또는 공유 카드로 이동 |
| 신고 재전송 | 네트워크·서버 처리로 제출이 완료되지 않음 | 실패 사실, 보존된 선택 사유·입력값, 다시 전송·취소 제어 | 동일 입력으로 재전송 |

신고 사유 분류 체계는 **(미정 — 확정 필요)** 이다. PM은 `P2b` 4번 결정과 `TRK-C` 집계 항목을 함께 확정하고, 그 전까지 화면은 서버가 제공한 사유 코드와 레이블만 사용한다. `EVD-D`의 재확인 처리 SLA도 **(미정 — 확정 필요)** 이며, 접수 화면은 완료 시각이나 처리 기한을 단정하지 않는다.

## 3. 카피

카피는 근거 속성, 단위, 확인 일자, 확인 주체와 같은 확인된 사실만 쓴다. 아래의 값은 실제 응답의 값으로 교체한다. 순위의 우열, 품질 또는 이용자 적합성을 단정하는 문구는 넣지 않는다.

| 사용 맥락 | 화면 카피 형식 |
| --- | --- |
| 공유 카드 선정 이유 | `좌석 간격 1.2m가 입력 조건 항목에 포함됨` |
| 공유 카드 근거 속성 | `근거 속성 좌석 간격 1.2m` |
| 공유 카드 확인 일자 | `확인 일자 2026-07-15` |
| 공유 카드 확인 주체 | `확인 주체 매장` |
| 신선도 | `확인 일자에서 90일 경과` |
| 공유 불가 | `확인 주체 항목이 없어 공유 카드를 만들지 않았습니다.` |
| 신고 시작 | `조건과 다른 사실을 선택하거나 입력해 주세요.` |
| 신고 접수 | `신고 접수 ID RPT-20260715-001 · 제출 시각 2026-07-15 14:20` |
| 신고 재전송 | `신고를 전송하지 못했습니다. 입력한 내용은 남아 있습니다.` |
| 재확인 안내 | `재확인 처리 시점은 (미정 — 확정 필요)입니다.` |

공유 카드의 근거 문장은 전체를 표시한다. 카드 컨테이너가 길어지면 세로 길이를 늘리며, 일부만 보이게 하거나 다른 문장으로 요약하지 않는다. 신고의 자유 입력은 신고자가 제공한 사실을 그대로 `EVD-D`에 전달하고 화면이 새로운 사실을 덧붙이지 않는다.

## 4. 컴포넌트

`CLI-C`는 `UX-A`의 shadcn/ui와 테마 토큰을 사용한다. 색상 코드, 임의 간격 값, 화면 전용 CSS 파일을 추가하지 않는다. 공유 데이터와 신고 상태는 화면 컴포넌트에서 조립하지 않고 각각 `EVD-C`, `EVD-D`의 검증된 응답을 입력으로 받는다.

| 컴포넌트 | 구성 | 불변 조건 |
| --- | --- | --- |
| `ShareCardPreview` | 매장 식별, `EvidenceBlock`, `FreshnessBadge`, 공유 생성 제어 | 근거 4항목이 모두 있을 때만 표시 |
| `SharedEvidenceCard` | 외부 공유용 매장 식별, 근거 4항목, 원본 열기 경로 | 확인 일자와 확인 주체가 카드 내부에 있음 |
| `ShareUnavailablePanel` | 누락 필드명, 공유 미생성 사실, 원본·조건 수정 제어 | 임시 템플릿 또는 누락값 대체 없음 |
| `FullEvidenceText` | 근거 문장 전문 | 말줄임·접기·길이 제한 없음 |
| `MismatchReportForm` | 신고 대상, 서버 제공 사유 선택, 사실 입력, 제출 제어 | 신고 대상 식별자가 없으면 제출 불가 |
| `ReportReceiptPanel` | 접수 식별자, 제출 시각, 처리 상태, 돌아가기 제어 | 처리 기한을 표시하지 않음 |
| `ReportRetryPanel` | 실패 사실, 유지된 입력, 재전송·취소 제어 | 실패 후 입력값을 초기화하지 않음 |

`EvidenceGate`를 통과한 후보만 `EVD-C`의 공유 생성 입력이 될 수 있다. `EVD-C`는 생성 전에 네 필드를 다시 확인하며, 하나라도 없으면 `400`을 반환한다. 이때 `ShareUnavailablePanel`은 서버 오류를 공유 카드로 바꾸지 않는다.

## 5. 근거

| 요구 또는 제약 | 설계 반영 |
| --- | --- |
| §8.3 규칙 1 · `REQ-FUNC-012` | 공유 카드 안에 선정 이유·근거 속성·확인 일자·확인 주체를 모두 표시한다. |
| SRS §4.5.3 | 네 필드 중 하나라도 없으면 공유 카드를 생성하지 않고, 누락 필드와 다음 행동이 있는 상태 영역을 보인다. |
| `REQ-FUNC-012` | 외부 공유 화면에서도 카드 내부만으로 근거 4항목을 확인할 수 있게 한다. |
| `REQ-FUNC-013` | 조건 불일치 신고는 대상 식별, 사유, 사실 입력, 접수 상태를 가진 흐름으로 구성한다. |
| §8.3 규칙 3 · `UX-C` · `WRITING-GUIDE.md` | 모든 화면 문장을 확인된 사실·단위·일자·주체 형식으로 제한한다. |
| §8.3 규칙 5 | 공유 불가, 신고 접수, 신고 재전송 모두에 사실과 다음 행동을 두어 빈 화면을 만들지 않는다. |

검증 시에는 (1) 근거 4항목이 외부 공유 카드 안에 모두 보이는지, (2) 하나라도 빠지면 카드가 만들어지지 않는지, (3) 긴 근거 문장이 전문으로 표시되는지, (4) 신고 전송 실패 후 선택 사유와 입력값이 남는지, (5) 접수 화면이 미정 SLA를 확정된 시각처럼 쓰지 않는지를 확인한다.

## 6. CLI 인계

| 수신 태스크 | 인계 내용 | 확인 기준 |
| --- | --- | --- |
| `CLI-C` | `ShareCardPreview`와 `SharedEvidenceCard`는 `EVD-C`가 검증한 네 근거 필드를 그대로 표시한다. | 공유 카드의 내부에서 네 레이블과 값, 특히 확인 일자·확인 주체를 읽을 수 있다. |
| `CLI-C` | 근거가 없는 입력에는 `ShareUnavailablePanel`만 표시하고 공유 링크·이미지·임시 템플릿을 생성하지 않는다. | `EVD-C`의 `400` 응답 뒤에도 빈 화면 없이 누락 필드와 원본·조건 수정 제어가 보인다. |
| `CLI-C` | `FullEvidenceText`는 근거 문장 전문을 표시하고 길이로 자르거나 요약하지 않는다. | 긴 문장 전체가 접근 가능한 텍스트로 존재한다. |
| `EVD-C` | 공유 생성 전 근거 4항목을 재검증하고 누락 시 `400` 및 누락 필드 식별자를 반환한다. | 화면이 누락 필드를 표시하며 공유 카드를 만들지 않는다. |
| `EVD-D` | 신고 대상 식별자, 서버 제공 사유 코드·레이블, 사실 입력, 접수 식별자·제출 시각·처리 상태를 처리한다. | 재전송 시 작성 내용이 유지되고, 접수 응답에 미정 SLA를 확정값으로 포함하지 않는다. |
| `EVD-D` | 신고 사유 체계와 재확인 SLA가 확정되기 전에는 해당 값을 임의 보완하지 않는다. | **(미정 — 확정 필요)** PM이 `P2b` 4번과 `TRK-C` 집계를 확정한 뒤 사유 레이블을 적용하고, 처리 SLA는 EVD-D 담당자와 PM이 확정한다. |
