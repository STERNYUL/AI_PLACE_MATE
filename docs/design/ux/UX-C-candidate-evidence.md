# UX-C · Top-3 카드·신선도·근거 라이팅

> 대상: `UX-004`, `UX-005`, `UX-015` · 선행: `UX-A` · 인계: `CLI-C`, `EVD-B`
> 근거: SRS §3.1.2, §8.3 규칙 1·3·4·5, `REQ-FUNC-002`, `REQ-FUNC-010`, `REQ-FUNC-011`, `REQ-FUNC-014`, `REQ-NF-011`

## 1. 화면 목록

후보 결과 화면은 조건 처리 완료 뒤에 진입한다. 결과 묶음은 근거 검증을 통과한 후보만 0~3개로 구성하며, 3개보다 많은 후보가 있어도 화면에는 최대 3개만 둔다. 카드의 표시 순서는 적합도를 첫 정렬 키로 사용한 결과를 따른다. 가격·거리·광고성 값을 노출 순서의 근거로 사용하지 않는다.

| 화면 또는 영역 | 진입 조건 | 화면에 남는 내용 |
| --- | --- | --- |
| Top-3 결과 | 근거 검증 통과 후보가 1~3개 | 후보 카드, 제외 수, 조건 수정 경로 |
| 후보 3개 미만 | 근거 검증 통과 후보가 0~2개 | 통과 후보, 수량 사실, 제외 수, 조건 수정 경로 |
| 신선도 표기 | 각 후보의 `verifiedAt` 산출 완료 | 확인 일자, 신선도 상태, 상태별 설명 |
| 근거 대기·생략 | `UX-F`의 해당 상태 진입 | 확인된 속성·일자·주체 또는 로딩 영역, 다음 행동 |

`RECHECK_REQUIRED` 후보는 결과 카드에 포함하지 않는다. 근거 4항목 중 하나라도 없는 후보도 정렬 전에 제외한다. 이 제외는 카드 수를 채우기 위한 대체로 무효화하지 않으며, 제외 수와 사유 구분은 상태 영역에 남긴다.

## 2. 상태

후보 수와 신선도는 별개로 다룬다. `STALE`은 확인 일자에서 90일이 경과한 사실을 알리고 후보를 유지한다. `RECHECK_REQUIRED`는 재확인이 완료되기 전 결과 카드에서 제외한다. 정확히 90일인 경계는 `STALE`이며, 89일 이하는 `FRESH`다.

| 상태 | 조건 | 카드 또는 상태 영역 | 다음 처리 |
| --- | --- | --- | --- |
| `FRESH` | 확인 일자 경과일 0~89일 | 확인 일자와 `확인 일자에서 90일 미만 경과` 표기 | 결과 유지 |
| `STALE` | 확인 일자 경과일 90일 이상 | 확인 일자와 `확인 일자에서 90일 경과` 배지를 카드 제목 아래에 독립 표시 | 결과 유지, 재확인 요청 경로 제공 |
| `RECHECK_REQUIRED` | 재확인 대상으로 판정 | 카드 대신 제외 수와 `재확인 대상 제외` 사실을 상태 영역에 표시 | 재확인 후 근거 게이트부터 다시 처리 |
| 3개 | 통과 후보 3개 | 카드 3개와 근거 4항목 | 결과 유지 |
| 2개 또는 1개 | 통과 후보 2개 또는 1개 | 통과 카드와 수량·제외 수·조건 수정 제어 | **(미정 — 확정 필요)** `SRC-D` 담당자와 PM이 3개 고정 요구와 근거 제외의 우선순위를 확정 |
| 0개 | 통과 후보 없음 | 조건, 제외 수, 구조화 필터 또는 재시도 제어 | `UX-F`의 비어 있지 않은 상태로 연결 |

신선도 배지는 색만으로 상태를 전달하지 않는다. 배지 안의 상태 텍스트와 확인 일자를 함께 보이며, 배지가 카드 정보 사이에 묻히지 않도록 카드 제목 다음에 둔다. `RECHECK_REQUIRED` 제외 수는 근거 누락 제외 수와 분리해 표시한다.

## 3. 카피

화면 문장은 확인된 사실 값·단위·확인 일자·확인 주체를 사용한다. 아래 표는 `WRITING-GUIDE.md`에 이관할 초안이며, 정본 확정 전에는 `EVD-B`와 `CLI-C`가 이 초안의 허용 형식만 사용한다. 판정형 기준의 최종 범위는 **(미정 — 확정 필요)** 이며 PM과 `EVD-B` 담당자가 확정한다.

| 사용 맥락 | 화면 카피 형식 |
| --- | --- |
| 선정 이유 | `좌석 간격 1.2m가 조건 항목에 포함됨` |
| 근거 속성 | `좌석 간격 1.2m` |
| 확인 일자 | `확인 일자 2026-07-15` |
| 확인 주체 | `확인 주체 매장` |
| `FRESH` | `확인 일자에서 90일 미만 경과` |
| `STALE` | `확인 일자에서 90일 경과` |
| `RECHECK_REQUIRED` 제외 | `재확인 대상 제외 1곳` |
| 근거 누락 제외 | `근거 항목 누락 제외 1곳` |
| 3개 미만 | `근거 검증 통과 후보 2곳` |

금지 초안은 결과 품질, 분위기, 순위의 우열, 이용자에게 맞는 정도를 단정하는 표현이다. 서버와 화면은 이 표현을 생성하거나 보완하지 않고, 해당 내용을 뒷받침하는 측정값·단위·일자·주체가 있으면 그 사실만 표기한다. 정본의 금지 목록과 차단 방식은 `WRITING-GUIDE.md` 확정 시 이 초안에서 이관한다.

## 4. 컴포넌트

`CLI-C`는 `UX-A`의 shadcn/ui 조합과 테마 토큰을 사용한다. 색상 코드, 임의 간격 값, 화면별 CSS 파일을 새로 두지 않는다. 각 컴포넌트는 근거 게이트 결과만 입력으로 받으며, 화면이 근거 필드를 조립하거나 신선도를 계산하지 않는다.

| 컴포넌트 | 구성 | 불변 조건 |
| --- | --- | --- |
| `CandidateCard` | 매장 식별, `EvidenceBlock`, `FreshnessBadge`, 행동 영역 | 근거 4항목이 모두 있을 때만 렌더 |
| `EvidenceBlock` | 선정 이유, 근거 속성, 확인 일자, 확인 주체 | 네 레이블과 값이 동시에 보임 |
| `FreshnessBadge` | `FRESH` 또는 `STALE` 텍스트, 확인 일자 | `STALE`을 색 단독으로 전달하지 않음 |
| `ExcludedCandidateSummary` | 근거 누락 제외 수, 재확인 대상 제외 수 | 두 제외 사유를 합쳐 표시하지 않음 |
| `CandidateCountPanel` | 통과 후보 수, 조건 수정 또는 재시도 제어 | 0~2개일 때도 본문과 행동을 유지 |

`EvidenceGate`는 `CandidateCard` props를 조립하는 유일한 경계다. 게이트 입력에서 `selectionReason`, `evidenceAttributes`, `verifiedAt`, `verifiedBy`가 모두 확인된 뒤에만 적합도 정렬 대상으로 넘긴다. `verifiedAt`은 신선도 계산의 단일 입력이며 카드 컴포넌트는 날짜 차이를 직접 계산하지 않는다.

## 5. 근거

| 요구 또는 제약 | 설계 반영 |
| --- | --- |
| §8.3 규칙 1 · `REQ-FUNC-010` · `REQ-FUNC-014` | 선정 이유·근거 속성·확인 일자·확인 주체가 모두 있는 후보만 카드로 표시한다. |
| §8.3 규칙 4 · `REQ-FUNC-002` | 근거 게이트를 적합도 정렬보다 먼저 실행하고, 결과 수는 0~3개로 제한한다. |
| `REQ-FUNC-011` · `REQ-NF-011` | 90일 미만, 정확히 90일, 90일 초과의 경계를 텍스트와 확인 일자로 드러내 경고 누락을 검증한다. |
| §8.3 규칙 3 · `UX-015` | 카피를 사실 값·단위·일자·주체 형식으로 제한한다. 판정형 차단 사전은 `EVD-B`와 하나의 정본을 사용한다. |
| §8.3 규칙 5 | 0개, 3개 미만, 제외 발생, 근거 대기·생략에서도 카드·사실·행동이 있는 상태 영역을 둔다. |

검증 시에는 (1) 근거 누락 후보가 정렬 입력에서 빠지는지, (2) `STALE` 카드가 확인 일자와 상태 텍스트를 동시에 보이는지, (3) `RECHECK_REQUIRED`가 카드가 아닌 별도 제외 수로 남는지, (4) 0~2개 결과가 비어 있는 본문을 만들지 않는지를 확인한다.

## 6. CLI 인계

| 수신 태스크 | 인계 내용 | 확인 기준 |
| --- | --- | --- |
| `CLI-C` | `EvidenceGate`를 정렬보다 앞에 두고, 네 근거 필드가 모두 있는 후보만 최대 3개 카드로 렌더한다. | 누락 후보와 `RECHECK_REQUIRED` 후보는 카드 목록에 없고, 각 제외 수가 분리되어 표시된다. |
| `CLI-C` | `FreshnessBadge`는 `verifiedAt`에서 계산된 상태만 받아 `FRESH`·`STALE`을 텍스트와 확인 일자로 표시한다. | 89일은 `FRESH`, 90일 및 그 초과는 `STALE`; `STALE` 카드가 결과에 남는다. |
| `CLI-C` | 0~2개 결과를 `CandidateCountPanel`과 `UX-F` 상태로 연결한다. | 카드 수, 제외 수, 조건 수정 또는 재시도 제어가 함께 보인다. **(미정 — 확정 필요)** 3개 고정 요구의 처리 우선순위는 `SRC-D` 담당자와 PM 확정 후 반영한다. |
| `EVD-B` | 이 문서 §3의 사실 서술 형식을 문장 생성 전 차단 기준으로 사용하고, `WRITING-GUIDE.md` 확정본으로 교체한다. | 생성 문장이 확인되지 않은 품질·순위·적합성 단정을 포함하지 않으며, 사실 문장은 근거 속성을 참조한다. |
| `EVD-B` | 신선도와 근거 검증 결과를 화면용 enum 및 제외 사유로 제공한다. | `FRESH`, `STALE`, `RECHECK_REQUIRED`, 근거 누락 제외 수가 `CLI-C`에 분리 전달된다. |

미정 항목을 확정하기 전에는 3개 미만의 결과를 임의 후보로 채우거나, 판정형 차단 목록을 임의 확장하지 않는다. `WRITING-GUIDE.md`는 공유 산출물로서 웨이브 합류 뒤 오케스트레이터가 이 초안을 이관한다.
