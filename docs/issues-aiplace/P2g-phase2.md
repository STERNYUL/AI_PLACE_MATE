## UX-G · 대화방 및 제안 비교 화면 설계 {#ux-g}

**labels** `design, ux, agent-room, priority:high, phase-2, conditional`
**원문** `UX-009` `UX-010`

### 🎯 Summary
- **Task ID** `UX-G` · **Should / H (H×1+M×1)** · **Phase 2 조건부**
- **목적** **180초라는 시간 제약을 화면 언어로 만든다.** 사용자가 기다리는 3분이 불안이 되면 안 된다.

### 🔗 References

- §3.1.2 · §3.1.4 · **§8.3 규칙 13**(서버 시각 기준) · 선행 `UX-A`

### ✅ Task Breakdown
- [ ] **`UX-009`** 대화방 화면 설계 — **카운트다운 표현**
- [ ] **`UX-010`** 제안 비교 화면 — **적합도 우선 정렬**
- [ ] 제안 0건 시 화면 — **Top-3 회귀** (`UX-F` 연동)
- [ ] 제안 도착의 점진적 표시 — 3분간 무엇을 보여줄지
- [ ] 소환 3~5곳의 상태 표현 — 응답/무응답
- [ ] 제안에 붙는 근거 표시 — `UX-C` 카드 규격 재사용

### ⚠️ 3분을 어떻게 보여줄 것인가

`REQ-FUNC-023`의 180초는 **매장이 응답할 시간**이지만, 사용자에게는 **기다리는 시간**이다.

| 나쁜 설계 | 좋은 설계 |
| --- | --- |
| 빈 화면 + 스피너 180초 | 소환된 매장이 보이고, 제안이 도착할 때마다 채워짐 |
| "3분 남음" 만 표시 | 지금 기다릴 가치가 있는지 판단할 재료 제공 |
| 0건이면 실패 화면 | **Top-3로 회귀** (`REQ-FUNC-025`) |

**§8.3 규칙 5(빈 화면 금지)가 여기서 가장 어렵게 적용된다** — 아직 아무것도 없는 3분이 정상 상태다.

### 🧪 Acceptance Criteria

**Scenario 1 · 정상 — 제안 도착**
- **Given** 대화방이 개시되고 제안이 순차 도착함
- **When** 화면을 봄
- **Then** 도착한 제안이 **적합도 순으로** 표시되고 남은 시간이 보인다

**Scenario 2 · 예외 (§4.5.3) — 제안 0건**
- **Given** 180초가 지나도 제안이 없음
- **When** 화면을 표시함
- **Then** **Top-3로 회귀**한다 (`REQ-FUNC-025`). 실패 화면이 아니다

**Scenario 3 · 경계 — 마감 직전 도착**
- **Given** 179초 시점에 제안이 도착함
- **When** 화면에 반영함
- **Then** **(미정)** 표시되는가, 마감 처리되는가. `AGT-B`의 서버 시각 판정을 따른다

**Scenario 4 · 근거 무결성 — 제안에도 근거**
- **Given** 매장이 보낸 제안
- **When** 화면에 표시함
- **Then** **근거 4항목이 붙어 있다.** 제안이라고 근거 규칙이 느슨해지지 않는다 (`AGT-C`)

### ⚙️ Technical & Non-Functional Constraints
- **`REQ-FUNC-023`** 180초 — **서버 시각 기준** (§8.3 규칙 13)
- **`REQ-FUNC-024`** 적합도 우선 정렬 — 가격순·거리순이 아니다
- **§8.3 규칙 5** 빈 화면 금지 — 대기 중에도 적용
- **§1.1 원칙** 노출 순서를 판매하지 않는다 — 제안 정렬도 같다

### 1회 클릭 수정이 요구인 이유

`REQ-FUNC-027`은 수정을 **1회 클릭**으로 규정한다. 이것은 편의가 아니라 **데이터 신선도 장치**다.

매장이 수정하기 번거로우면 갱신하지 않고, 갱신되지 않으면 90일 뒤 `STALE`이 되어 경고가 붙는다.
**콘솔 사용성이 곧 `REQ-FUNC-011` 신선도의 실질 결정 요인이다.**

- **When** 저장을 시도함
- **Then** **차단되고 사실 진술로 바꾸도록 안내**된다 (§8.3 규칙 7 · `UX-C` 라이팅 가이드)

- **Then** **1회 클릭으로 수정 화면에 도달**한다 (`REQ-FUNC-027`)

**Scenario 4 · 근거 무결성 — 확인 주체 기록**
- **Given** 매장이 정보를 입력함
- **When** 저장함
- **Then** **확인 주체가 해당 매장으로, 확인 일자가 저장 시각으로** 기록된다 (`SPEC-008`)
