## TEST-006 · 근거 4항목 무결성 검증 {#test-006}

**labels** `test, verification, evidence, priority:critical, phase-1, identity`
**대상** `REQ-FUNC-010` `014` · **TC** `TC-FUNC-010·014`

### 🎯 Summary
- **Task ID** `TEST-006` · **Must / H**
- **목적** **근거 없는 정보가 어떤 경로로도 나가지 않음을 증명한다.** 이 프로젝트의 최상위 불변 규칙.

### 🔗 References
- **§1.1** · **§4.5.1** · **§8.3 규칙 1** · `REQ-FUNC-010` · `REQ-FUNC-014`
- 계약 **`SPEC-008`** · §5.1 `TC-FUNC-010·014`
- 대응 구현 `EVD-A`(검증기) `SRC-D`(정렬) `EVD-C`(공유) `AGT-C`(제안) `CLI-C`(렌더)

### ⚠️ 네 소비처가 같은 결론을 내는지가 핵심이다

`P1a-contracts.md`가 `SPEC-008`을 만든 이유이자, `P2b`의 `EVD-A` 시나리오 4가 요구한 것이다.

```
SPEC-008 근거 4항목 정의
   ├─→ SRC-D  정렬 전 필터
   ├─→ EVD-C  공유 카드 400 판정
   ├─→ AGT-C  제안 등록 거부
   └─→ CLI-C  렌더 차단
```

**네 곳이 다르게 판정하면, 어느 한 곳으로 근거 없는 정보가 새어 나간다.**
이 태스크는 **동일 입력을 네 경로에 넣고 결론을 대조**한다.

### ✅ Task Breakdown
- [ ] `TC-FUNC-010·014` 실행 케이스 전환
- [ ] **4항목 각각의 누락 케이스** — 4종 (`MOCK-003`)
- [ ] **네 소비처 대조 테스트** — 동일 입력 → 동일 결론
- [ ] `Attribute` 참조 실패 케이스
- [ ] `STALE` · `RECHECK_REQUIRED` 판정 검증 (`SPEC-008` 확정 반영)
- [ ] **전 응답 경로 스캔** — 근거 없는 필드가 나가는 경로 탐색

### 🧪 검증 시나리오

**정상** — 4항목 완비 후보가 네 경로 모두에서 통과한다
**예외 (§4.5.3)** — 확인 주체 누락 후보가 **네 경로 모두에서 차단**된다
**경계** — `STALE` 후보의 처리가 네 경로에서 **동일**하다 (`SPEC-008` 확정안)
**불변 규칙** — **근거 4항목 중 하나라도 없는 정보가 외부로 나가는 경로가 0개**다

### ⚙️ Constraints
- **§8.3 규칙 1** — 이 프로젝트의 최상위 규칙
- **위반 0건이 기준** — 통과율 99%는 실패다
- `SPEC-008`의 `STALE` 유효성 미정이 이 태스크의 경계 케이스를 막고 있다

### 🏁 DoD
공통 5개. 추가로 —
- [ ] **네 소비처 대조가 전부 일치하는가?**
- [ ] 4항목 누락 4종이 모두 차단되는가?
- [ ] 근거 없는 정보의 유출 경로가 **0개**인가?
- [ ] `STALE` 판정이 확정되어 케이스에 반영되었는가?

### 🚧 Dependencies & Blockers
- **Depends on** `SPEC-008` `EVD-A` `SRC-D` `EVD-C` `CLI-C`
- **Blocks** Phase 1 게이트 신뢰성
- **미정 — 확정 필요** **`STALE` 후보 유효성** (`SPEC-008` · `P2b` 최우선)
