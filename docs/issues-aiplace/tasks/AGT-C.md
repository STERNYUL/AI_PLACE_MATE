### ⚠️ 가중치 하향은 매장에 대한 제재다

`REQ-FUNC-026`은 불이행 시 **가중치를 하향**하라고 규정하지만 **폭도, 회복 조건도 없다.**

| 미정 | 결과 |
| --- | --- |
| 하향 폭 | 1회 불이행에 얼마나? |
| 회복 조건 | 이행하면 돌아오는가, 시간이 지나면? |
| 하한 | 계속 내려가면 사실상 퇴출인가 |
| 고지 | 매장이 자기 가중치를 아는가 |

**가중치는 소환 순서에 영향을 준다** — `AGT-A`의 소환 선정 규칙과 같은 자리에서 정해져야 하고,
**§1.1의 "노출 순서를 판매하지 않는다"와 정합해야 한다.** 불이행 기반 하향은 판매가 아니지만,
**규칙이 불투명하면 판매와 구별되지 않는다.**

### 🧪 Acceptance Criteria

**Scenario 1 · 정상 — 제안 등록**
- **Given** 매장이 근거 4항목을 갖춘 제안을 보냄
- **When** 등록함
- **Then** 검증을 통과해 방에 반영되고 적합도 순으로 정렬된다

**Scenario 2 · 예외 (§4.5.3) — 근거 없는 제안**
- **Given** 확인 주체가 없는 제안
- **When** 등록을 시도함
- **Then** **거부된다** (`EVD-A` 재사용). 제안이라고 규칙이 느슨해지지 않는다

**Scenario 3 · 경계 — 제안 0건**
- **Given** 180초 동안 제안이 없음
- **When** 마감함
- **Then** **Top-3로 회귀**한다 (`REQ-FUNC-025` · `SRC-D` 결과 재사용)

**Scenario 4 · 근거 무결성 — 불이행 기록의 근거**
- **Given** 불이행으로 가중치를 하향함
- **When** 근거를 조회함
- **Then** **어느 예약의 어떤 불이행인지 추적 가능**하다. 근거 없는 제재는 §1.1 원칙에 어긋난다
