### ⚠️ 라이팅 가이드가 서버 검증 기준이 된다

`EVD-B`는 생성 문장에서 **판정형 문구를 차단**해야 하는데, **무엇이 판정형인지 SRS에 규칙이 없다**(P2b 미정 1번).

**그 기준을 만드는 것이 `UX-015`다.** 그리고 그 기준은 두 곳에서 쓰인다 —

```
UX-015 라이팅 가이드
   ├─→ EVD-B 서버 문장 생성 시 판정형 차단 사전
   └─→ CLI-C 화면 카피 작성 기준
```

**두 곳이 다른 기준을 쓰면 서버가 통과시킨 문장이 화면에서 판정형이 된다.**
가이드는 디자인 문서이자 **검증 규격**이다.

| 판정형 (금지) | 사실 진술 (허용) |
| --- | --- |
| "조용한 분위기입니다" | "소음 45dB · 2026-08-01 매장 확인" |
| "단체에 적합합니다" | "8인 테이블 보유 · 2026-08-01 매장 확인" |
| "가성비가 좋습니다" | "인당 18,000원 · 2026-07-15 메뉴판 확인" |

### 🧪 Acceptance Criteria

**Scenario 1 · 정상 — Top-3 카드**
- **Given** 근거 4항목을 가진 후보 3곳
- **When** 카드를 설계함
- **Then** **선정 이유 · 근거 속성 · 확인 일자 · 확인 주체**가 모두 카드 안에 자리를 갖는다

**Scenario 2 · 예외 (§4.5.3) — 후보 3개 미만**
- **Given** 근거 검증 통과 후보가 2곳
- **When** 화면을 설계함
- **Then** **(미정)** 2곳만 보이는가, 상태를 알리는가. `SRC-D`의 "3개 고정 ↔ 근거 제외" 충돌과 같은 항목

**Scenario 3 · 경계 — `STALE` 카드**
- **Given** 90일 경과 후보
- **When** 카드를 설계함
- **Then** **경고가 묻히지 않는 위계**로 표시된다. 작게 회색으로 넣으면 `REQ-NF-011` 0%를 형식만 충족한다

**Scenario 4 · 근거 무결성 — 라이팅 가이드 일치**
- **Given** `UX-015` 가이드와 `EVD-B` 판정형 사전
- **When** 대조함
- **Then** **동일하다.** 별도 문서라면 한쪽이 정본이고 다른 쪽이 참조한다
