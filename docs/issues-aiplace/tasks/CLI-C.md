### ⚠️ 클라이언트가 마지막 방어선이다

`EVD-A`가 서버에서 근거를 검증하지만, **클라이언트도 렌더 직전에 확인해야 한다.**

이유는 단순하다 — 서버 검증을 우회하는 경로(캐시, 이전 버전 응답, 목 잔존)가 실제로 생긴다.
**`REQ-NF-011`의 경고 누락률 0%는 화면에 나온 것으로만 판정된다.**
서버가 경고를 보냈어도 화면에 안 뜨면 누락이다.

### 🧪 Acceptance Criteria

**Scenario 1 · 정상 — Top-3 렌더**
- **Given** 근거 4항목이 완비된 후보 3곳
- **When** 화면을 렌더함
- **Then** 각 카드에 **선정 이유 · 근거 속성 · 확인 일자 · 확인 주체**가 표시된다

**Scenario 2 · 예외 (§4.5.3) — 근거 누락 응답**
- **Given** 응답에 확인 주체가 없는 후보가 섞임 (`MOCK-003`)
- **When** 렌더를 시도함
- **Then** **그 후보를 렌더하지 않고** 상태를 표시한다. 근거 없는 카드는 화면에 나오지 않는다

**Scenario 3 · 경계 — `STALE` 후보**
- **Given** 90일이 경과한 확인 정보 (`MOCK-004`)
- **When** 카드를 렌더함
- **Then** **신선도 경고가 반드시 표시**된다. 누락률 **0%** (`REQ-NF-011`)

**Scenario 4 · 근거 무결성 — 판정형 문구 0건**
- **Given** 화면에 렌더된 모든 문구
- **When** 판정형 검증을 수행함
- **Then** **0건**이다. 서버(`EVD-B`)와 클라이언트(`UX-C` 가이드)가 같은 기준을 쓴다
