### ⚠️ '유사 메뉴'의 정의가 SRS에 없다

평가서 §4가 지적한 항목이다. `REQ-FUNC-007`은 유사 메뉴를 대체 반환하라고 하지만
**무엇이 유사한지 판정 기준이 없다.**

| 후보 기준 | 문제 |
| --- | --- |
| `canonical_key` 계층 (상위 카테고리 일치) | 사전에 계층이 정의돼 있어야 한다 — `IDX-A` FR-010 |
| 문자열 유사도 | "돈까스"와 "돈까스덮밥"이 유사한가 |
| 함께 주문되는 메뉴 | 데이터가 없다 (v0.1) |

**`IDX-A`의 조건 카테고리 사전에 메뉴 계층을 포함시키는 것이 현실적**이나, 그러면 `IDX-A` 범위가 늘어난다. **확정 필요.**

### 🧪 Acceptance Criteria

**Scenario 1 · 정상 — 메뉴명 질의**
- **Given** 메뉴명과 지역
- **When** 질의함
- **Then** 반경 **1km** 내에서 해당 메뉴를 제공하는 매장이 반환된다

**Scenario 2 · 예외 (§4.5.3) — 정확 일치 0곳**
- **Given** 반경 1km에 해당 메뉴가 없음
- **When** 질의함
- **Then** **유사 메뉴로 대체**하고 **대체했다는 사실을 명시**한다 (`REQ-NF-010`)

**Scenario 3 · 경계 — 반경 1km 경계**
- **Given** 정확히 1,000m 거리의 매장
- **When** 질의함
- **Then** 포함된다 (이하 판정) — 단위 **m** (§8.1.1)

**Scenario 4 · 근거 무결성 — 대체 사실 은닉 금지**
- **Given** 유사 메뉴로 대체된 후보
- **When** 응답을 확인함
- **Then** **대체 사실이 반드시 포함**된다. 은닉하면 `REQ-NF-010` 위반이고 사용자가 오인한다
