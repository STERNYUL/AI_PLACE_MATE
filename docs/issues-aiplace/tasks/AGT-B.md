### ⚠️ 단방향 채널 방식이 인앱 브라우저에 걸린다

`FR-045`는 **단방향 채널**을 요구한다. 방식은 SSE·WebSocket·롱폴링 중 하나다.

**그런데 진입 경로가 네이버 지도 앱 내 탭이다**(`CLI-A` R6).
인앱 브라우저가 SSE나 WebSocket을 안정적으로 유지하는지는 **실측 대상**이며,
`CLI-A`의 인앱 제약 실측 항목에 이것이 포함돼야 한다.

**Phase 1에서 실측해 두면 Phase 2 착수 시 재작업이 없다.**

### 🧪 Acceptance Criteria

**Scenario 1 · 정상 — 180초 수명**
- **Given** 대화방이 생성됨
- **When** `expiresAt`을 확인함
- **Then** **생성 시각 + 180초**이며 **서버 시각 기준**이다 (§8.3 규칙 13)

**Scenario 2 · 예외 (§4.5.3) — 채널 끊김**
- **Given** 네트워크가 끊겼다 복구됨
- **When** 재연결함
- **Then** **끊긴 동안 도착한 제안이 복구**되고 남은 시간이 서버 기준으로 재계산된다

**Scenario 3 · 경계 — 마감 시각 제안**
- **Given** `expiresAt` 직전·직후 제안 도착
- **When** 판정함
- **Then** **서버 시각으로 판정**한다. 클라이언트 시각을 신뢰하지 않는다

**Scenario 4 · 근거 무결성 — 카운트다운 일치**
- **Given** 클라이언트 카운트다운과 서버 `expiresAt`
- **When** 대조함
- **Then** **어긋나지 않는다.** 클라이언트가 먼저 0이 되면 사용자는 도착한 제안을 놓친다
