### ⚠️ v1.1 선행 정정의 근거

v1.0은 `UX-F`의 선행을 `UX-003` · **`UX-009`(Phase 2 대화방)** 로 적었다.
`REQ-FUNC-025`의 *"제안 0건 시 Top-3 회귀"* 가 대화방과 연결되기 때문이다.

**그러나 Top-3 회귀 화면을 설계하는 데 대화방 설계가 필요하지 않다.**
필요한 것은 **회귀 대상인 Top-3 화면**(`UX-C`)이다.

§0.1의 *"없으면 착수 자체가 불가능한 것만"* 규칙을 적용해 선행을 `UX-B` · `UX-C`로 바꿨고,
**Phase 1 태스크가 Phase 2를 기다리는 구조가 해소됐다.**

### 상태마다 '다음 행동'이 있어야 한다

§8.3 규칙 5가 금지하는 것은 **빈 화면**이지만, 실질 요구는 **막다른 길 금지**다.
"결과가 없습니다"만 있고 할 수 있는 일이 없으면 빈 화면과 다르지 않다.

| 상태 | 다음 행동 |
| --- | --- |
| 후보 0건 | 조건 완화 제안 (`SRC-B` 미정 3번) |
| 파싱 실패 | 폴백 필터 (`UX-B`) |
| 제안 0건 | **Top-3 회귀** (`REQ-FUNC-025`) |
| 서버 오류 | 재시도 · 조건 유지 |
| 근거 미비로 후보 제외 | **(미정)** `SRC-D` 3개 고정 충돌 |

### 🧪 Acceptance Criteria

**Scenario 1 · 정상 — 상태 전수 정의**
- **Given** 각 화면의 가능한 상태
- **When** 설계를 확인함
- **Then** **모든 상태에 화면과 다음 행동**이 정의돼 있다

**Scenario 2 · 예외 (§4.5.3) — 제안 0건**
- **Given** 대화방에서 제안이 하나도 오지 않음
- **When** 화면을 표시함
- **Then** **Top-3로 회귀**한다 (`REQ-FUNC-025`). Phase 2 발동 시 적용

**Scenario 3 · 경계 — 후보 0건**
- **Given** 조건을 만족하는 후보가 없음
- **When** 화면을 표시함
- **Then** **(미정)** 조건 완화를 제안하는가, 없음만 알리는가 (`SRC-B` 미정 3번)

**Scenario 4 · 근거 무결성 — 상태 카피의 정확성**
- **Given** "근거 확인 중" 같은 상태 카피
- **When** 실제 시스템 동작과 대조함
- **Then** **일치한다.** 없는 동작을 암시하는 카피를 쓰지 않는다
