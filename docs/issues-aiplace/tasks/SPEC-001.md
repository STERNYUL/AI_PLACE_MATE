### 상태 코드 체계 (제안 — SRS에 `400`·`5xx`만 존재)

| 코드 | 사용 조건 | SRS 근거 |
| --- | --- | --- |
| `200` | 정상 | — |
| `400` | 계약 위반 — **근거 4항목 누락**(§4.5.1) · 등록 속성 미참조 문구(§8.1.1) · 조건 2개 미만 | §8.1.1 명시 |
| `401` | 미인증 | `REQ-NF-018` |
| `422` | 파싱 불가 **(제안)** | `REQ-FUNC-009` 폴백 전환과 구분 필요 |
| `5xx` | 서버 오류 — **`REQ-NF-008` 오류율 산정 대상** | `REQ-NF-008` |

**`422`를 제안하는 이유가 있다.** `REQ-FUNC-009`는 파싱 실패 시 **구조화 필터로 폴백**하라고 규정한다.
즉 파싱 실패는 오류가 아니라 **정상 흐름의 분기**다. `400`으로 반환하면 클라이언트가 폴백을 트리거할 수 없고,
`REQ-NF-009`(파싱 실패율 5분 윈도 집계)의 분모도 오염된다.

### 🧪 Acceptance Criteria

**Scenario 1 · 정상 — 추적 ID 전파**
- **Given** `X-Request-Id`가 없는 요청
- **When** Gateway를 통과해 3개 서비스를 거침
- **Then** ID가 생성되어 전 구간에 전파되고, `IN-C`(IN-004) 계측에서 **하나의 요청으로 추적**된다

**Scenario 2 · 예외 (§4.5.3) — 외부 추론 서비스 장애**
- **Given** 조건 파서(`SRC-A` · FR-011)가 응답하지 않음
- **When** `POST /v1/query`를 호출함
- **Then** `422`가 아니라 **폴백 전환 신호**를 반환하고, 클라이언트가 구조화 필터 UI로 전환한다. `5xx`가 아니므로 `REQ-NF-008` 오류율에 포함되지 않는다

**Scenario 3 · 경계 — 오류율 산정 경계**
- **Given** `4xx` 100건 · `5xx` 1건이 발생한 1,000건 구간
- **When** `REQ-NF-008` 오류율을 산정함
- **Then** **0.1%** 로 계산된다 (`4xx`는 분자에서 제외)

**Scenario 4 · 근거 무결성 — 해당 없음**
- 이 태스크는 후보·제안을 반환하지 않는다. `SPEC-008`이 담당한다
