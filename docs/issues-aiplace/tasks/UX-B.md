### ⚠️ 전환 고지의 카피가 이 태스크의 산출물이다

`REQ-FUNC-009`는 전환을 **고지**하라고만 규정한다. **무엇이 좋은 고지인지는 디자인 판단**이다.

파싱 실패는 §4.5.3의 **정상 분기**이지 오류가 아니다(`SPEC-002` 참조).
그런데 카피가 "오류가 발생했습니다"가 되면 **정상 동작이 실패로 전달**된다.

| 원칙 | 적용 |
| --- | --- |
| 사용자를 탓하지 않는다 | "잘못 입력하셨습니다" ✗ |
| 다음 행동을 준다 | "조건을 직접 선택해 주세요" ○ |
| 입력을 버리지 않는다 | 인식된 값은 필터에 채워 둔다 |

### 🧪 Acceptance Criteria

**Scenario 1 · 정상 — 자연어 입력 흐름**
- **Given** 조건 입력 화면
- **When** 사용자가 자연어를 입력함
- **Then** 파싱 결과가 **확인·수정 가능한 형태**로 표시된다

**Scenario 2 · 예외 (§4.5.3) — 폴백 전환**
- **Given** 파싱이 실패함
- **When** 폴백 필터로 전환함
- **Then** **전환이 고지되고, 오류가 아니라 다음 행동으로 읽히는 카피**가 표시된다

**Scenario 3 · 경계 — 부분 파싱**
- **Given** 일부 조건만 인식됨
- **When** 화면을 설계함
- **Then** **(미정)** 인식분 이월 표현. `CLI-B`와 같은 결정을 공유한다

**Scenario 4 · 근거 무결성 — 임의 조건 추가 없음**
- **Given** 파싱 결과 화면
- **When** 표시 내용을 확인함
- **Then** **사용자가 말하지 않은 조건이 기본값으로 채워지지 않는다.** 채운다면 그 사실이 보여야 한다

### ⚙️ Technical & Non-Functional Constraints
