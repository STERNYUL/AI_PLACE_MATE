### ⚠️ '판정형 문구'의 판정 기준이 없다

§8.3 규칙 3과 §1.1은 판정을 금지한다. 예시도 있다 — *"'조용하다' 같은 주관적 판정"*.
그런데 **무엇이 판정형인지 가르는 규칙이 SRS에 없다.**

| 문장 | 판정형인가 |
| --- | --- |
| "2026-08-01 매장 확인: 좌석 간 간격 1.2m" | ✗ 사실 진술 |
| "조용한 분위기입니다" | ○ 주관적 판정 |
| "소음 측정 45dB (2026-08-01 매장 확인)" | ✗ 사실 + 출처 |
| "단체 모임에 적합합니다" | **?** — 적합 판단인가 조건 매칭 진술인가 |

**세 번째 행이 경계다.** 조건 매칭 결과를 문장으로 쓰면 판정처럼 읽힌다.
`UX-C` 라이팅 가이드와 **같은 자리에서** 어휘 기준을 정해야 한다.

**차단 방식도 정해야 한다** — 어휘 사전 차단인지, 생성 후 검증인지, 둘 다인지.

### 🧪 Acceptance Criteria

**Scenario 1 · 정상 — 근거 문장 생성**
- **Given** 근거 4항목이 완비된 후보
- **When** 선정 이유 문장을 생성함
- **Then** 근거 속성과 확인 일자·주체가 문장에 드러나고 **판정형 표현이 없다**

**Scenario 2 · 예외 (§4.5.3) — 추론 서비스 장애**
- **Given** 문장 생성 서비스가 응답하지 않음
- **When** 후보를 반환함
- **Then** **(미정 — 확정 필요)** 대체 문안인지 후보 제외인지. 제외하면 `SRC-D` 3개 고정과 충돌

**Scenario 3 · 경계 — 90일 당일**
- **Given** `verified_at + 90일`이 정확히 경과한 후보
- **When** 표기를 생성함
- **Then** 경고가 **병기**되고 `STALE` 전이가 반영된다 (`REQ-FUNC-011`)

**Scenario 4 · 근거 무결성 — 판정형 0건**
- **Given** 생성된 문장 전수
- **When** 판정형 검증을 실행함
- **Then** **0건**이다. `REQ-NF-011` 경고 누락률 0%와 함께 이 제품의 두 불변 규칙이다
