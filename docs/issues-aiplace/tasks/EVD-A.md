### ⚠️ 정렬 이전 배치가 이 태스크의 설계 조건이다

§4.5.2가 *"정렬 이전 단계 배치"* 를 규정한 이유가 있다.

```
정렬 후 필터   후보 10개 정렬 → 상위 3개 선택 → 근거 검증 → 1개 탈락 → 2개만 남음
정렬 전 검증   후보 10개 → 근거 검증 → 7개 통과 → 정렬 → 상위 3개  ✓
```

**정렬 후에 거르면 Top-3가 3개 미만이 된다.** 검증을 앞에 두어야 3개를 채울 수 있다.
그럼에도 통과 후보가 3개 미만이면 `SRC-D`의 미정 항목("3개 고정 ↔ 근거 제외 충돌")이 발동한다.

### 🧪 Acceptance Criteria

**Scenario 1 · 정상 — 4항목 완비 통과**
- **Given** 선정 이유·근거 속성·확인 일자·확인 주체가 모두 있는 후보
- **When** 검증함
- **Then** 통과하고 정렬 대상에 포함된다

**Scenario 2 · 예외 (§4.5.3) — `Attribute` 참조 실패**
- **Given** 근거 속성이 가리키는 `attribute` 레코드가 없음
- **When** 검증함
- **Then** **탈락**하고 결락 사유가 기록된다. 참조 없는 근거는 근거가 아니다

**Scenario 3 · 경계 — `STALE` 후보**
- **Given** `verified_at + 90일`이 경과한 `STALE` 후보
- **When** 검증함
- **Then** **(미정 — 확정 필요)** `SPEC-008`의 판정을 따른다. 통과 + 경고 병기인지, 탈락인지

**Scenario 4 · 근거 무결성 — 네 소비처 일관성**
- **Given** 동일 후보를 `SRC-D` · `EVD-C` · `AGT-C` · `CLI-C`가 각각 판정함
- **When** 결과를 대조함
- **Then** **네 곳이 동일한 결론**을 낸다. 이 시나리오가 `SPEC-008`이 존재하는 이유다
