### ⚠️ 3~5곳을 무엇으로 고르는가

`REQ-FUNC-022`는 **3~5곳**을 규정하지만 **선정 기준이 없다.**

수용 조건을 만족하는 매장이 20곳이면 어느 5곳인가 —
`SRC-D`의 정렬 결과 상위 5곳인가, 무작위인가, 응답률 높은 순인가.

**§1.1의 "노출 순서를 판매하지 않는다"가 여기에도 적용된다.**
기준이 없으면 색인 순서가 사실상 소환 순위가 된다 — `SRC-D` 동점 규칙 부재와 같은 구조의 공백이다.

### 🧪 Acceptance Criteria

**Scenario 1 · 정상 — 대화방 개시**
- **Given** 수용 조건을 만족하는 매장 5곳
- **When** 대화방 개시를 요청함
- **Then** 방이 생성되고 5곳에 소환이 발송된다

**Scenario 2 · 예외 (§4.5.3) — 소환 0곳**
- **Given** 조건을 만족하는 매장이 없음
- **When** 개시를 요청함
- **Then** **방을 만들지 않고 즉시 미개시**를 반환한다 (`REQ-FUNC-022`). Top-3 회귀로 연결

**Scenario 3 · 경계 — 2곳만 가능**
- **Given** 조건 만족 매장이 2곳
- **When** 개시를 요청함
- **Then** **(미정)** 3곳 미만이면 개시하는가. "3~5곳"이 하한을 뜻하면 미개시다

**Scenario 4 · 근거 무결성 — 선정 재현성**
- **Given** 동일 조건으로 두 번 요청
- **When** 소환 대상을 비교함
- **Then** **(미정)** 같아야 하는가. 재현 불가능하면 공정성을 검증할 수 없다
