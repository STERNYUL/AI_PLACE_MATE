### 🧪 Acceptance Criteria

**Scenario 1 · 정상 — 300건 적재**
- **Given** 상권 1곳의 원천 데이터
- **When** 초기 적재를 실행함
- **Then** **300건**이 적재되고 각 건의 **필수 필드 5개**가 채워져 있다

**Scenario 2 · 예외 — 필수 필드 결락**
- **Given** 필수 5개 중 일부가 없는 원천 레코드
- **When** 적재를 시도함
- **Then** **적재를 거부하고 결락 항목을 로그에 남긴다** (확정 · Grill S3-T8). 300건이 부족하면 **원천을 확대해 채운다**

### 필수 필드 결락 — 거부한다. 기준을 낮춰 채우지 않는다 (확정 · Grill S3-T8)

| 상황 | 처리 |
| --- | --- |
| 필수 5개 중 일부 결락 | **적재 거부** + 어느 항목이 비었는지 로그 |
| 300건 미달 | **원천 확대** — 상권 범위·수집처를 늘린다 |

**세션 2 T3(Top-3의 3은 상한)과 같은 모양이다** — *채우려고 기준을 낮추지 않는다.*

**부분 적재를 허용하지 않는 이유가 둘이다.**

| # | 내용 |
| --- | --- |
| 1 | §3.1.6이 **"필수"** 라고 규정한 5개다. 부분 적재를 허용하면 그 규정이 사실상 무효가 된다 |
| 2 | 색인에 근거 없는 레코드가 쌓이면 **`EvidenceGate`가 유일한 방어선**이 된다 — `C-DRV-004`가 RLS에 대해 경고한 것과 같은 구조다. 게이트 버그 1건이 곧 근거 없는 후보 노출이다 |

**Phase 0 게이트가 재는 것은 "300건이 적재됐다"가 아니라 "필수 필드를 갖춘 300건이 있다"이다.**
부분 적재로 300을 채우면 **게이트를 통과한 것처럼 보이지만 실제로는 미달**이다.

**항목별 차등을 기각한 이유** — "필수"가 필수가 아니게 되고 항목별 기준이 새 미정이 된다. `SPEC-008`이 근거 4항목을 **동등하게** 취급하기로 한 것과도 충돌한다.

**Scenario 3 · 경계 — 재색인**
- **Given** 스키마 변경이 발생함
- **When** 전면 재색인을 실행함
- **Then** 300건이 무손실로 재구성되고 소요 시간이 측정된다 (ADR-001 비용 실측)

**Scenario 4 · 근거 무결성 — 적재 시점 확인 상태**
- **Given** 적재된 레코드
- **When** `IDX-D`(FR-007)가 `Verification`을 부여함
- **Then** **확인 일자·주체가 없는 레코드가 후보로 나가지 않는다**
