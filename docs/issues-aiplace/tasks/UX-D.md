### ⚠️ 공유 카드는 앱 밖에서 혼자 읽힌다

카드는 메신저·SNS로 나가 **우리 화면의 맥락 없이** 읽힌다.
확인 일자와 주체가 카드 이미지 안에 없으면, **근거 없는 추천으로 유통된다.**

`EVD-C`가 근거 누락 시 `400`을 반환하는 이유가 이것이고,
**템플릿이 4항목을 담을 자리를 확보하지 못하면 서버 검증이 무의미해진다.**

### 🧪 Acceptance Criteria

**Scenario 1 · 정상 — 공유 카드**
- **Given** 근거 4항목을 가진 후보
- **When** 카드 템플릿을 적용함
- **Then** **이미지 안에 확인 일자와 주체가 읽히는 크기로** 포함된다

**Scenario 2 · 예외 (§4.5.3) — 근거 누락**
- **Given** 4항목 중 하나가 없음
- **When** 카드를 만들려 함
- **Then** **생성되지 않는다** (`EVD-C` `400`). 디자인에도 "누락 시 대체 템플릿"을 두지 않는다

**Scenario 3 · 경계 — 긴 근거 문장**
- **Given** 선정 이유가 템플릿 영역을 넘음
- **When** 렌더함
- **Then** **잘리지 않는 처리**가 필요하다. 잘린 근거는 왜곡이다

**Scenario 4 · 근거 무결성 — 신고 후 피드백**
- **Given** 사용자가 불일치를 신고함
- **When** 완료 화면을 봄
- **Then** **재확인 절차가 진행됨이 안내**된다. `EVD-D`의 처리 SLA 미정이 여기서 카피 공백이 된다

### ⚙️ Technical & Non-Functional Constraints
- **`REQ-FUNC-012`** 공유 카드 — 근거 포함
- **§8.3 규칙 1** 외부 유통물에도 근거 무결성 적용
- **회수 불가** — 나간 카드는 되돌릴 수 없다
- 신고 플로우는 **신뢰의 마지막 경로** — 마찰이 크면 아무도 신고하지 않는다
