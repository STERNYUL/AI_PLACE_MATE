## SRC-A · 조건 파싱 · 폴백 · 실패율 경보 {#src-a}

**labels** `feature, backend, search-service, priority:high, phase-1`
**원문** `FR-011` `FR-012` `FR-013` `FR-020`

### 🎯 Summary
- **Task ID** `SRC-A` · **Must / H (H×1+M×2+L×1)**
- **목적** 사용자가 아무것도 입력하지 않아도 검색이 되게 하고, 파서가 죽어도 서비스가 죽지 않게 한다.

### 🔗 References
- SRS §3.1.7(외부 추론 서비스) · §4.5.3(예외 처리) · §8.1.1 · §6.3
- `REQ-FUNC-008`(필수 입력 0개) · `REQ-FUNC-009`(폴백) · `REQ-NF-009`(실패율 5분 윈도) · `REQ-NF-019`(추론 비용 12원)
- 계약 `SPEC-001`(`422` vs 폴백 신호) · `SPEC-002`

### ✅ Task Breakdown
- [ ] **`FR-011`** 자연어 조건 파서 연동 (외부 추론 서비스)
- [ ] **`FR-012`** 파싱 실패 시 **구조화 필터 폴백 전환**
- [ ] **`FR-013`** 필수 입력 없는 질의 수용 — 필수 필드 **0개**
- [ ] **`FR-020`** 파싱 실패율 **5분 윈도** 집계 및 경보 연동
- [ ] 외부 서비스 타임아웃·재시도 정책
- [ ] 세션당 추론 비용 계측 연동 (`TRK-E`)

### ⚠️ 파싱 실패는 오류가 아니다

`SPEC-001`에서 제안한 `422` 구분의 근거가 여기 있다.
`REQ-FUNC-009`는 파싱 실패 시 **폴백 전환**을 규정한다 — 즉 **정상 흐름의 분기**다.

**`5xx`로 반환하면 `REQ-NF-008` 오류율에 잡히고, `400`으로 반환하면 클라이언트가 폴백을 트리거할 수 없다.**
그리고 `REQ-NF-009`의 실패율 분모는 **전체 질의 수**여야 하는데, 오류로 처리하면 그 계산이 어긋난다.

### 🧪 Acceptance Criteria

**Scenario 1 · 정상 — 자연어 파싱**
- **Given** 자연어 조건 1줄
- **When** 파싱함
- **Then** 구조화 조건으로 변환되고 `SRC-B`·`SRC-C` 필터의 입력이 된다

**Scenario 2 · 예외 (§4.5.3) — 외부 추론 서비스 장애**
- **Given** 추론 서비스가 응답하지 않거나 타임아웃됨
- **When** 질의를 처리함
- **Then** **폴백 전환 신호**를 반환하고 구조화 필터 후보군으로 진행한다. **`5xx`가 아니다**

**Scenario 3 · 경계 — 조건 0개 질의**
- **Given** 조건·지역·인원이 **전부 비어 있는** 요청
- **When** 처리함
- **Then** 거부하지 않고 후보 선별로 진행한다 (`REQ-FUNC-008` 필수 필드 0개)

**Scenario 4 · 근거 무결성 — 실패율 집계 정확성**
- **Given** 5분 동안 질의 100건 중 파싱 실패 3건
- **When** `REQ-NF-009` 실패율을 집계함
- **Then** **3%** 로 산출된다. 폴백된 질의가 분모에서 빠지지 않는다

### ⚙️ Technical & Non-Functional Constraints
- **`REQ-NF-009`** 파싱 실패율 **5분 윈도** 집계 · Phase 0 게이트 **≤ 3%**
- **`REQ-NF-019`** 세션당 추론 비용 **12원 상한** — 재시도가 비용을 늘린다
- **§4.5.3** 외부 서비스 장애 시 서비스는 계속 동작해야 한다
- 외부 연동 — **일정이 자사 통제 밖** (원장 §6)

### 🏁 DoD
공통 DoD 5개. 추가로 —

- [ ] 실패율 분모가 전체 질의 수인지 확인했는가?

### ⚠️ 예산 판정 기준값이 SRS에 없다

`PriceProfile`은 **하한·평균·상한 세 값**을 갖는다(`IDX-A`).
그런데 `REQ-FUNC-003`의 *"예산 상한 필터"* 가 **어느 값과 비교하는지** SRS에 없다.

| 기준 | 결과 |
| --- | --- |
| 하한 비교 | 후보가 넓어진다. "갔더니 예산 초과" 위험 |
| 평균 비교 | 중간. 가장 무난 **(제안)** |
| 상한 비교 | 후보가 좁아진다. Fill 부족 위험 |

**`REQ-FUNC-002`가 "인당가 범위"를 노출하므로 사용자는 범위를 본다.** 판정은 평균으로 하고 범위를 함께 보이는 편이 정합적이나, **확정 필요.**

### 🧪 Acceptance Criteria

**Scenario 1 · 정상 — 예산 필터**
- **Given** 예산 상한과 후보군
- **When** 필터를 적용함
- **Then** 상한 이내 후보만 남고 **'예산 초과 N곳'** 요약이 함께 반환된다

**Scenario 2 · 예외 (§4.5.3) — 조건 충족 후보 0곳**
- **Given** 조건이 너무 좁아 후보가 0곳
- **When** 필터를 적용함
- **Then** **(미정 — 확정 필요)** 필터 완화인지 빈 결과인지. 빈 결과면 `UX-F` 빈 화면 금지와 연결

**Scenario 3 · 경계 — 예산 = 인당가**
- **Given** 예산 상한과 후보 인당가가 **정확히 같음**
- **When** 필터를 적용함
- **Then** 포함된다 (이하 판정)

**Scenario 4 · 근거 무결성 — 조건 카테고리 근거**
- **Given** '주차 가능'으로 필터된 후보
- **When** 근거를 확인함
- **Then** **`Attribute`에 근거가 있는 후보만** 남는다. 추정으로 필터하지 않는다

### ⚙️ Technical & Non-Functional Constraints
- 조건 카테고리 어휘는 **상권별로 다르다** (`IDX-A` FR-010)
- 이 필터는 **정렬 이전** 단계다 — `EVD-A` 근거 검증과 순서 조율 필요 (§4.5.2)
- 상태 비저장

### 🏁 DoD
공통 DoD 5개. 추가로 —

### 🔗 References

- `REQ-FUNC-014`(Top-3 고정) · `REQ-NF-001`(p95) · §4.5.2(정렬) · §8.1 · §8.1.1 · §8.3 규칙 2

### ⚠️ "3개 고정"과 "근거 없는 후보 제외"가 충돌한다

`SPEC-002` Scenario 4가 지적한 항목이다. §8.1이 두 규칙을 **동시에** 요구한다.

```
후보 정확히 3개              ← REQ-FUNC-014 · §8.1
근거 없는 후보 반환 금지      ← §8.1
```

**근거 결락으로 정렬 대상이 2개만 남으면 무엇을 반환하는가.** SRS에 답이 없다.
`SPEC-008`의 `STALE` 유효성 판정과 **같은 뿌리**이며, 함께 결정해야 한다.

### 🧪 Acceptance Criteria

**Scenario 1 · 정상 — Top-3 반환**
- **Given** 조건과 근거 4항목 완비 후보 다수
- **When** `POST /v1/query`를 호출함
- **Then** `200`과 후보 **정확히 3개**, 각 후보에 §8.1.1의 여섯 필드가 있고 **p95 ≤ 1,000ms**다

**Scenario 2 · 예외 (§4.5.3) — 파싱 실패 폴백**
- **Given** `SRC-A`가 폴백 전환 신호를 반환함
- **When** 질의를 처리함
- **Then** 구조화 필터 후보군으로 Top-3를 구성하고 **전환 사실을 응답에 실어** 클라이언트가 고지하게 한다

**Scenario 3 · 경계 — 정렬 동점**
- **Given** 적합도가 동일한 후보가 4개 이상
- **When** Top-3를 구성함
- **Then** **(미정 — 확정 필요)** 동점 규칙이 SRS에 없다. 규칙이 없으면 **먼저 색인된 후보가 항상 이긴다**

**Scenario 4 · 근거 무결성 — 정렬 이전 배치**
- **Given** 근거 4항목 중 하나가 결락된 후보
- **When** 정렬을 수행함
- **Then** **그 후보는 정렬에 참여하지 않는다** (§4.5.2). 정렬 후 필터가 아니다 — 그러면 3개를 못 채운다

### ⚙️ Technical & Non-Functional Constraints
- **§8.1** p95 **≤ 1,000ms** · 후보 **정확히 3개** · 근거 없는 후보 반환 **금지**
- **§8.3 규칙 2** 페이지네이션 없음
- **§4.5.2** 근거 검증은 **정렬 이전**
- **`REQ-NF-001` 측정 조건 미정** — 데이터량·RPS·캐시 상태 (평가서 §4)
- **광고 상품 없음** — 노출 순서를 판매하지 않는다 (§1.1 핵심 원칙)
