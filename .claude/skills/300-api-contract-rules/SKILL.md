# API 계약

근거 — `[SRS]ai-place -mate-SRSv1.0.md` §8.1·§8.1.1 · `SPEC-001` 공통 규약(이슈 `#94`)

**`SPEC-001`이 나머지 계약 8건을 막는다.** 새 엔드포인트를 만들기 전에 그 태스크의 확정 사항을 확인한다.

## 명명
- 리소스는 **복수 명사** — `/v1/places`, `/v1/proposals`
- URL은 **kebab-case** — `/v1/share-cards`, `/v1/agent-rooms`
- **URL에 동사를 넣지 않는다.** HTTP 메서드로 표현한다

## 메서드
`GET` 조회(안전·멱등) · `POST` 생성 · `PUT` 전체 교체(멱등) · `PATCH` 부분 수정 · `DELETE` 제거

## 상태 코드

| 코드 | 조건 |
| --- | --- |
| `200` | 정상 |
| `201` | 생성됨 |
| `400` | **계약 위반** — 근거 4항목 누락 · 등록 속성 미참조 문구 · 조건 2개 미만 |
| `401` | 미인증 (전 API 인증 필수 · `REQ-NF-018`) |
| ~~`422`~~ | **쓰지 않는다** (Grill T8) — 파싱 실패는 §4.5.3 **정상 분기**다. `200` + `fallbackApplied: true`로 반환한다. `4xx`로 보내면 클라이언트가 오류 경로에서 폴백을 트리거해야 하고 `REQ-NF-009` 파싱 실패율 분모가 오염된다 |
| `5xx` | 서버 오류 — **`REQ-NF-008` 오류율 산정 대상** |

> **`400`과 폴백을 혼동하지 않는다.** 자연어 파싱 실패는 오류가 아니라 **정상 경로의 분기**다 (규칙 2).
> `400`은 근거 없는 데이터를 만들려 할 때다.

## 인증 — 전 API 필수 (`REQ-NF-018`)

`Authorization: Bearer <JWT>` — **Supabase 익명 세션**으로 발급한다 (Grill T7). 미인증은 `401`.

**로그인을 요구하지 않는다** — `REQ-FUNC-008`이 필수 입력 0개를 규정한다. 익명이라도 주체가 있어야 `auth.uid()`로 RLS가 작동한다 (`C-DRV-004`).
**쿠키를 쓰지 않는다** — 진입이 지도 앱 내 탭(R6)이라 인앱 브라우저의 쿠키·스토리지 정책에 걸릴 수 있다. 헤더는 무관하다.
매장 콘솔만 정식 로그인 + MFA(TOTP)로 승격한다.

## 단위 — SRS §8.1.1 그대로

금액 **원** · 거리 **m** · 지연 **ms** · 인원 **명** · 만료 **s**

**반올림·요약하지 않는다.** SRS의 수치를 그대로 옮긴다.

### 임계값은 경계를 포함한다 — `≤` / `≥`

계약에 임계값을 쓸 때 **경계값을 포함하는 쪽으로 읽는다.** `CLAUDE.md` §7 임계값 경계 규약이 정본이다.

- 신선도 **90일 이상** 경과 → `STALE` (90일 당일부터 경고)
- p95 **≤ 1,000ms** · **≤ 400ms** · **≤ 3,000ms** — 경계값 달성은 통과
- 파싱 실패율 **3% 이하** 통과 · 캐시 히트율 **70% 이상** 통과

OpenAPI `description`과 테스트 경계값(89/90/91일 같은 3종)이 이 규약과 어긋나면 **계약이 틀린 것이다.**

## JSON
- 속성명 **camelCase**
- 날짜 **ISO-8601**
- `null` 필드는 생략 (명시적 `null`이 의미를 가질 때만 유지)

### 근거 4항목 필드명 — 네 곳이 같은 이름을 쓴다

| JSON 키 | 데이터 출처 | 성격 |
| --- | --- | --- |
| `selectionReason` | **없음 — 파생** (`EVD-B` 생성) | 진술 |
| `evidenceAttribute` | `Attribute.name` · `value` | 저장된 사실 |
| `verifiedAt` | `Verification.verified_at` | 저장된 사실 |
| `verifiedBy` | `Verification.verified_by` — **열거형 4종** | 저장된 사실 |

소비처가 `EVD-A`·`EVD-C`·`AGT-C`·`CLI-C` 네 곳이므로 **한 곳이 다른 이름·출처를 쓰면 통합에서 터진다.**

**`selectionReason`은 저장하지 않는다** (Grill T5). `Evidence` 엔터티를 만들지 않는다 — 저장하면 판정형 사전이 갱신돼도 과거 문장이 남아 §8.3 규칙 3이 깨진다.

**`verifiedBy`는 열거형이다** (Grill S3-T2) — `MERCHANT` · `INTERNAL_SURVEY` · `USER_REPORT` · `OPERATOR`. 표시 문구는 `lib/evidence` 매핑 함수 한 곳이 만든다.
자유 텍스트로 두면 **매장 확인이 아닌데 "사장 확인"으로 쓰는 사칭을 스키마가 막지 못하고**, 판정형 어휘 검사가 DB 값까지 쫓아가야 한다.

### 항목의 속성인가, 결과 전체의 속성인가

**후보·제안 배열의 항목에는 SRS가 명시한 필드만 넣는다.** 결과 전체를 설명하는 값은 **응답 최상위**에 둔다 (Grill T4).

| 최상위 | 왜 |
| --- | --- |
| 폴백 전환 신호 · 유사 메뉴 대체 사실 | 질의 전체에 일어난 일이다 |
| '예산 초과 N곳' 요약 · 제외 사유별 건수 | 특정 후보의 값이 아니다 |

항목에 넣으면 **같은 값이 항목 수만큼 중복**되고, **배열이 비면 실을 곳이 사라진다.**
배열 길이로 알 수 있는 값(통과 건수 등)은 **싣지 않는다** — 중복이다.

**같은 원칙이 스키마에도 적용된다** (Grill S3-T3). 다른 컬럼에서 그대로 나오는 사실은 별도 컬럼으로 저장하지 않는다 — `PriceProfile`의 단일값 여부는 `min`·`max`로 알 수 있으므로 플래그를 두지 않고, 축약 표시는 `lib/<domain>`이 한다.

### `Verification` 3상태 — 소비처 4곳이 같은 표를 따른다

| 상태 | 정렬 참여 | 노출 | 경고 |
| --- | --- | --- | --- |
| `VERIFIED` | 참여 | 노출 | 없음 |
| `STALE` | **참여** | **노출** | **병기 필수** — 누락률 0% (`REQ-NF-011`) |
| `RECHECK_REQUIRED` | **제외** (정렬 이전 · §4.5.2) | — | — |

**`STALE`은 제외 사유가 아니라 경고다** (`CLAUDE.md` §2 규칙 3). 반면 `RECHECK_REQUIRED`는 **불일치 신고 접수 상태**이므로 재확인 전까지 내보내지 않는다 — 확인되지 않은 정보를 계속 노출하면 §8.3 규칙 1 위반이다.

**캐시된 응답도 수신 시점에 다시 판정한다** (Grill T6). 캐시 TTL 6시간 구간 안에서 90일이 경과하면 서버가 붙인 상태는 이미 낡았다.
그래서 응답에는 **상태가 아니라 `verifiedAt`이 실려야** 하고, 판정은 `lib/evidence/freshness.ts` **한 함수**가 한다 — 서버도 클라이언트도 각자 날짜를 계산하지 않는다.

`EVD-A`·`EVD-C`·`AGT-C`·`CLI-C` 어느 쪽도 **이 표를 재정의하지 않는다.**

### wire ↔ 컴포넌트 props 변환은 한 곳에서

DB는 snake_case, API는 camelCase다. 변환은 `lib/<domain>/client.ts`의 단일 함수에서만 한다.
**컴포넌트가 wire 형식을 직접 읽지 않는다** — 표기가 바뀌면 그 함수 하나만 고친다.

## 페이지네이션 없음 · Top-3는 **상한**이다
`REQ-FUNC-014`의 Top-3에 페이지네이션을 만들지 않는다.

**3은 상한이지 고정값이 아니다** (Grill T3). 근거 게이트를 통과한 후보가 3곳 미만이면 **그만큼만 반환한다** — 0~3개.
3개를 채우려 기준을 낮추면 불변 규칙 1과 `REQ-IMPL-010`(`EvidenceGate`가 정렬보다 앞)을 깬다.

응답에 **통과 건수와 그 사실**을 실어 화면이 상태를 사실로 고지하게 한다. 0개는 열화 상태 `제안없음`으로 간다 — **빈 화면이 아니다.**

## 오류 응답
`{ code, message, requestId }` — `requestId`는 추적 헤더(`X-Request-Id`)와 같은 값이다. SLO 계측(`IN-C`)과 연결된다.

**리소스 부재도 `400`이다** (Grill T10). `404`를 신설하지 않는다 — 클라이언트가 보낸 id가 계약과 맞지 않는 경우이므로 `400`("계약 위반") 정의에 들어간다.

**근거 4항목 누락은 `message`에 항목명을 넣는다.**

```json
{ "code": "EVIDENCE_MISSING", "message": "확인 주체 누락", "requestId": "..." }
```

4항목은 동등하게 취급되므로 **구현이 실수로 3개만 검사할 수 있다.** 항목명이 없으면 그 실수가 드러나지 않고, `MOCK-003`의 항목별 누락 4종 검증이 무의미해진다.

## 웹훅 (외부 → 우리)
- **서명을 검증한다**
- **중복 수신을 전제한다.** 조건부 UPDATE로 멱등 처리
- 이미 처리된 이벤트도 **`200`으로 응답**한다. 오류를 주면 PG가 무한 재전송한다
