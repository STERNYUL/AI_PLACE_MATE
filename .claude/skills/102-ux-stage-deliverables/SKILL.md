# UX 단계 산출물 규격

근거 — `docs/issues-aiplace/P2f-ux.md` 공통 DoD · 기준 SRS §3.1.2·§8.3 · `REQ-IMPL-008`~`010`

**UX 태스크의 산출물은 코드가 아니라 문서다.** 그래서 완료 판정도 문서로 한다.
`ux-design-system` 에이전트가 *무엇을* 설계할지 정하고, 이 스킬이 *어디에 어떤 형식으로* 남길지 정한다.

## 1. 파일 경로 — 고정

```
docs/design/ux/
  UX-A-design-system.md        토큰 · 공통 컴포넌트 · 성능 예산 · 안전 영역
  UX-B-search-entry.md         조건 입력 · 폴백 필터 UI · 전환 고지
  UX-C-candidate-evidence.md   Top-3 카드 · 신선도 경고 · 근거 라이팅
  UX-D-share-report.md         공유 카드 템플릿 · 불일치 신고 플로우
  UX-E-reservation-privacy.md  예약·결제·취소 · 옵트인 동의
  UX-F-empty-states.md         열화 6상태
  WRITING-GUIDE.md             판정형 어휘 금지 목록 — UX-C 산출, 전 문서가 참조
```

Phase 2 조건부(`UX-G` 대화방 · `UX-H` 매장 콘솔)는 `docs/design/ux/phase2/`에 따로 둔다.
**게이트 미통과 시 그 디렉터리만 통째로 이월된다.**

## 2. 문서 구조 — 6개 절 고정

| 절 | 내용 |
| --- | --- |
| `## 1. 화면 목록` | 이 태스크가 다루는 화면과 진입 경로 |
| `## 2. 상태` | 각 화면의 상태와 전이. **빈 화면이 없음을 여기서 보인다** |
| `## 3. 카피` | 실제 문구. **판정형 어휘 0건** |
| `## 4. 컴포넌트` | 쓰는 shadcn 컴포넌트. 새로 만들면 `UX-A`에 소급 추가 |
| `## 5. 근거` | 어느 요구사항·SRS 절에서 온 제약인지 |
| `## 6. CLI 인계` | 대응 `CLI-` 태스크가 확인해야 할 것 |

**`## 6`이 없으면 완료가 아니다.** 공통 DoD의 *"`CLI-` 담당자가 확인했는가"* 가 여기서 판정된다.

## 3. 판정형 어휘 — 금지 목록

`WRITING-GUIDE.md`가 정본이다. 최소한 아래는 들어간다 (§8.3 규칙 3).

```
조용  아늑  분위기 좋  분위기 나쁨  추천  최고  훌륭  괜찮  무난
가성비  인기  핫한  숨은 맛집  강추  별로
```

**대체 형식** — 사실 + 출처 + 일자.

```
✗  "조용한 편이에요"
○  "좌석 간격 1.2m · 2026-07-15 · 사장 확인"
```

## 4. 완료 판정 명령

**`gh`·`git`·텍스트 도구만으로 판정한다.** 이 단계에는 Node가 필요 없다.

```bash
# 산출물 6종 존재
find docs/design/ux -maxdepth 1 -name 'UX-*.md' | wc -l          # equals 6

# 판정형 어휘 0건 (§8.3 규칙 3)
grep -rniE '조용|아늑|분위기 (좋|나쁨)|추천|최고|훌륭|괜찮|무난|가성비|인기|핫한|강추|별로' \
  docs/design/ux/ --include='*.md' | grep -v 'WRITING-GUIDE'      # returns 0 matches

# 6개 절이 다 있는 문서만 완료
for f in docs/design/ux/UX-*.md; do
  n=$(grep -cE '^## [1-6]\. ' "$f"); echo "$f $n"                 # 각 6
done

# 열화 6상태 (§8.3 규칙 5)
grep -cE '^\| (폴백표시|근거대기|근거생략|유사메뉴대체|제안없음|재시도안내)' \
  docs/design/ux/UX-F-empty-states.md                             # equals 6
```

## 5. 이 단계가 무엇을 푸는가

**`UX-C`의 판정형 어휘 기준이 임계 경로를 막고 있다.**

```
UX-C ──→ EVD-B ──→ EVD-C ──→ CLI-C ──→ TEST-007
        (문장 생성)          (Top-3 화면)
```

기준이 없으면 `EVD-B`가 "무엇을 차단해야 하는지" 모른 채 착수한다.
**UX 단계를 먼저 끝내는 실질 이유가 이것이다** — 디자인 취향이 아니라 임계 경로 해제다.

## 6. 착수를 막는 것

| 태스크 | 미정 | 누가 |
| --- | --- | --- |
| `UX-A` | **`UX-001` 인정 여부** — SRS에 대응 요구사항이 없는 유일 항목 | PM |
| `UX-A` | 접근성 기준 — SRS에 없다 | PM |
| `UX-C` | **판정형 어휘 기준** — 이 태스크가 PM과 공동으로 만든다 | PM + 디자인 |
| `UX-E` | **개인정보 보존 기간** — 없으면 동의 카피를 쓸 수 없다 | 법무 |

**미정인 채로 진행하되, 그 항목을 문서에 `(미정 — 확정 필요)`로 남긴다.** 빈칸은 합의된 것처럼 보인다.
