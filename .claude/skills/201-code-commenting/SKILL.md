# 주석

## 원칙
- **WHY만 쓴다.** WHAT은 코드로 표현한다
- 코드를 읽으면 아는 것을 주석으로 반복하지 않는다
- 오래되어 사실과 다른 주석은 **즉시 제거**한다. 틀린 주석은 없는 것만 못하다

## 이 프로젝트에서 주석이 필요한 자리

**제약이 코드에 안 보이는 곳**이다.

| 상황 | 적을 것 |
| --- | --- |
| 조건부 UPDATE / 조건부 INSERT | 왜 잠금 대신 이 형태인지 (Pooler transaction mode) |
| `status` 대신 지연 평가 술어 | 왜 컬럼을 믿지 않는지 (Cron 정규화 전 레코드) |
| 캐시 제외 결정 | 왜 캐시하면 안 되는지 (예: 확인 상태 60초 반영) |
| 게이트 순서 | 왜 정렬보다 앞인지 (후보 3개 미만 경로 차단) |
| `'use client'` | 왜 클라이언트여야 하는지 (타이머·구독·입력 상태·localStorage) |
| 매직 넘버 | 어느 요구사항에서 온 값인지 (`REQ-NF-011` 90일 등) |

**요구사항 ID를 적는다.** `// REQ-NF-002: p95 400ms — 캐시 히트 경로 유지` 처럼.
