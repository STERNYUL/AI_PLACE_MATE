# 오류 열화

근거 — 기준 SRS §8.3 규칙 5 · 런타임 SDD §7.3 · `REQ-IMPL-013`

**빈 화면을 반환할 수 있는 코드 경로 자체를 만들지 않는다.** 실패는 상태로 표현한다.

## 상태 6종

```
정상 ──AI 파싱 실패·시한 초과──→ 폴백표시 ──구조화 조건 제출 성공──→ 정상
 │
 ├──근거 문장 스트림 지연──→ 근거대기 ──문장 도착──→ 정상
 │                            └──스트림 실패──→ 근거생략
 ├──색인 미등재──→ 유사메뉴대체
 ├──유효 제안 0건──→ 제안없음 ──→ Top-3 회귀
 └──DB·PG 오류──→ 재시도안내 ──재시도 성공──→ 정상
```

| 상태 | 화면 처리 | 근거 |
| --- | --- | --- |
| **폴백표시** | 구조화 필터 UI + 전환 고지. **Top-3는 계속 표시** | `REQ-FUNC-009` |
| **근거대기** | 카드 골격과 사실 값 표시, **문장 자리만 로딩** | `REQ-IMPL-015` |
| **근거생략** | 문장 없이 속성·확인 일자만. **카드를 숨기지 않는다** | `REQ-FUNC-010` |
| **유사메뉴대체** | 대체 사실을 문구로 명시 | `REQ-FUNC-007` |
| **제안없음** | 빈 제안 화면 대신 **제안 없는 Top-3** | `REQ-FUNC-025` |
| **재시도안내** | 사유와 재시도 수단 제시 | §8.3 규칙 5 |

## `근거생략`이 규칙 1과 충돌하지 않는 이유

규칙 1이 요구하는 4항목은 **선정 이유 · 근거 속성 · 확인 일자 · 확인 주체**다.
이 중 **선정 이유 문장의 생성이 실패**한 경우, 사실 속성 3항목과 **규칙 기반 기본 문구**로 4항목을 채운다.

**AI 실패가 카드 소멸로 이어지지 않게 하는 것이 설계 의도다.**

## 실패를 던지지 않는다

```ts
// ✓ 분기
async function resolve(input: QueryInput): Promise<ResolvedCondition> {
  try { return await viaAi(input.text) }
  catch { return { ...viaStructured(input), fallbackUsed: true } }
}

// ✗ 예외를 위로 던지면 화면이 비는 경로가 생긴다
async function resolve(input: QueryInput) {
  return await viaAi(input.text)   // 실패하면?
}
```

## 후보가 부족할 때

**빈 배열을 화면까지 올리지 않는다.**

```
통과 후보 ≥ 3?  예 → 정렬 → Top-3
                아니오 → 조건 완화 후 모집단 재구성 → 다시 게이트
```

조건 완화로도 안 되면 **유사 메뉴 대체**나 **폴백 고지**로 내려간다. 어느 경로든 화면에 무언가가 남는다.

## 열화가 발생했음을 기록한다

- `parse_result` — `success` · `fallback_used`
- 근거 표기 누락 — **1건 발생 시 즉시 알림**
- 조용히 열화되면 품질 저하를 모르고 지나간다
