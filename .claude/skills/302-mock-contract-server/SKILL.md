# Mock 서버

근거 — `docs/issues-aiplace/P1c-mock.md` · 평가서 §1 · 태스크 `MOCK-001`~`008`

**Mock 8건의 존재 이유는 하나다 — 프론트엔드가 백엔드를 기다리지 않게 하는 것.**
이게 성립해야 SRS §4.3.3이 전제한 3스트림 병행이 돈다.

## 계약이 먼저다

Mock은 **계약(`SPEC-001`~`009`)에서 파생**된다. 계약 없이 Mock을 만들면 실 API와 어긋난다.

| Mock | 대응 계약 |
| --- | --- |
| `MOCK-001` 기반 구성 | `SPEC-001` 공통 규약 |
| `MOCK-002` Top-3 조회 | `SPEC-002` |
| `MOCK-003` 근거 4항목 | `SPEC-002` · `SPEC-008` |
| `MOCK-004` 신선도 3상태 | `SPEC-002` |
| `MOCK-005` 공유 카드 | `SPEC-004` |
| `MOCK-006` 대화방 | `SPEC-005` |
| `MOCK-007` 예약·결제 | `SPEC-007` |
| `MOCK-008` 매장 콘솔 | **`SPEC-010` 미신설** — 블로커 |

## 자동 검증이 없으면 Mock이 거짓말을 한다

**공통 DoD** — 응답이 `docs/api-aiplace.yaml` 스키마 검증을 **자동으로** 통과해야 한다.
**수동 대조는 반드시 어긋난다.** 계약이 바뀌었는데 Mock이 그대로면 클라이언트가 잘못된 전제로 만들어진다.

- 계약 변경 시 **Mock 갱신을 강제하는 절차**가 있어야 한다
- 이 자동 검증이 실제로 도는 것이 **Mock 기반 분리(압축 일정 §2.3)의 전제**다

## 세 가지를 반드시 재현한다

| 경로 | 왜 |
| --- | --- |
| **정상** | 기본 |
| **예외** | 근거 누락 `400` · 파싱 실패 · 결제 거절 — 클라이언트가 이 경로를 안 만들면 빈 화면이 난다 |
| **경계·지연** | p95 초과 지연 주입 — 로딩·타임아웃 처리 검증 |

**시나리오를 스위치로 전환**할 수 있어야 한다. 재빌드 없이 바꿀 수 있어야 클라이언트가 쓴다.

## 근거 없는 응답을 만들 수 없어야 한다

`MOCK-003`·`MOCK-005`의 **불변 규칙 시나리오**다.
Mock이 근거 4항목 없는 후보를 반환할 수 있으면, 클라이언트가 그 경로를 정상으로 오해한다.
**계약이 금지하는 응답은 Mock도 만들 수 없다.**

## 폐기 시점을 정해둔다

공통 DoD에 있다 — **실구현 완료 후 폐기 시점이 정해져 있는가.**
정하지 않으면 Mock과 실 API가 영원히 공존하며 어긋난다.
