# 에러 진단 — 7단계

대상: **$ARGUMENTS**

**추측으로 고치지 않는다.** 각 단계에서 근거를 남긴다.

## 1. 현상 정의
관측된 것만 적는다 — 에러 메시지 원문, 재현 조건, 발생 빈도. 해석은 아직 하지 않는다.

## 2. 범위 탐색
관련 파일·데이터 흐름·호출 경로를 짚는다. 이 프로젝트에서 자주 걸리는 지점 —

| 증상 | 먼저 볼 곳 |
| --- | --- |
| `PrismaClient is unable to run in this environment` | Edge 런타임에서 DB 접근 (`nextjs-runtime` §1) |
| `prepared statement ... already exists` | Pooler transaction mode 위반 (`data-access` §1) |
| 캐시가 갱신 안 됨 | 태그 무효화 누락 · 기본값 의존 (`nextjs-runtime` §2) |
| 클라이언트에서 남의 데이터가 보임 | **RLS 정책 누락** (`data-access` §4) — 최우선 |
| Cron이 중간에 끊김 | 함수 시간 상한 · 부분 완료 미구현 |
| 카드가 안 그려짐 | 근거 4항목 중 누락 (`domain-invariants` 규칙 1) |

## 3. 근본 원인 특정
증거와 함께 좁힌다. **증상이 아니라 원인을 적는다.**

## 4. 중급 개발자 기준으로 요약
전문 용어를 풀어 설명한다. 이 단계에서 설명이 막히면 원인을 아직 모르는 것이다.

## 5. 수정 지점 제시
고칠 곳과 이유를 나열한다. 부수 영향 범위도 같이 적는다.

## 6. 수정
의도를 보존하며 최소로 고친다. **4대 불변 규칙을 깨는 우회는 하지 않는다** — 규칙을 지키면서 고칠 방법을 찾는다.

## 7. 후속 제안
재발 방지 — 테스트, 로깅, 정적 검사, 타입 강제 중 무엇이 맞는지 제시한다.
동일 클래스 오류가 다른 곳에 있는지 `grep`으로 확인한다.
