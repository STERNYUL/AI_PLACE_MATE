# 계측 · KPI · SLO

근거 — `[SRS]ai-place -mate-SRSv1.0.md` §6.1·§6.3 · `[DIAGRAMS]DESIGN-ai-place-v1.0.md` §6.3 · `REQ-IMPL-023`

## 1. 발행은 비동기, 집계 장애가 이용자를 막지 않는다

```
도메인 서비스 ─(비동기)→ 큐 → 필수 속성 검증 → tracking_events(occurred_at 파티션)
                                    ↓ 누락
                                 누락 카운터 → 공표 게이트
```

**서버리스 주의** — 응답 후 실행이 보장되지 않는다. 적재 호출은 **응답 반환 이전에 시작**하되 완료를 기다리지 않는다.

## 2. 누락률 게이트 — 5% 넘으면 공표하지 않는다

집계 결과를 그냥 내보내지 않는다. **누락률 ≤ 5%** 를 통과해야 `kpi_weekly_snapshot`에 들어간다.
초과하면 **미공표 + 사유 기록**이다. 신뢰 구간 없이 지표를 공표하지 않는다 (§6.1.3).

## 3. 정제 순서를 지킨다

```
원천 → 내부·봇 트래픽 제외 → 세션 재구성(30분 무활동) → 중복 제거 → 집계
```

중복 제거 키는 `session_id` / `anon_user_id` / 도메인 ID다.

## 4. 집계 주기

| 주기 | 지표 |
| --- | --- |
| 일간 | 보조 2 · 4 · 8 |
| 주간 | **북극성(WEBD)** · 보조 1 · 3 · 7 |

## 5. 알림 임계 — 즉시 대응 대상

| 조건 | 조치 |
| --- | --- |
| **근거 표기 누락 1건** | 즉시 알림 |
| 파싱 실패율 5분 윈도 > 3% | 알림 + 파서 롤백 |
| 노쇼율 주간 > 8% | 신규 노출 중단 |
| 5xx > 0.3% · **결제 API > 0.1%** | 결제는 분리 계측한다 |

## 6. 집계 쿼리는 시각으로 판정한다

`status` 컬럼으로 집계하면 **Cron 정규화 전 레코드가 섞인다.** 시각 기반 술어를 쓴다.

```sql
-- 보조 8: 3분 내 제안 도착률
count(*) FILTER (
  WHERE EXISTS (
    SELECT 1 FROM "Proposal" p
    WHERE p."roomId" = r.id AND p."submittedAt" <= r."expiresAt"
  )
)::float / nullif(count(*), 0)
```

## 7. 기준선이 없으면 판정 불가로 표시한다

KPI 기준선 15건이 Phase 0 종료 시점에 실측된다. 그 전에는 **통과로 처리하지 않고 판정 불가로 남긴다.**
`REQ-NF-029`(결정 시간 20% 단축)처럼 비교 대상이 필요한 지표가 여기 해당한다.

## 8. 체크리스트

- [ ] 이벤트 적재가 응답을 막지 않는가 (그러나 응답 전에 시작하는가)
- [ ] 누락률 게이트를 통과해야 공표되는가
- [ ] 집계 술어가 `status`가 아니라 시각 기반인가
- [ ] 결제 오류율을 분리 계측하는가
- [ ] 기준선 미실측 항목이 통과로 세지지 않는가
