# 4대 불변 규칙

근거 — `[SRS]ai-place -mate-SRSv1.0.md` §8.3 · `[DIAGRAMS]DESIGN-ai-place-v1.0.md` §6.1 · `DESIGN-ai-place-nextjs-v1.0.md` §7.2·§7.3

**이 넷은 태스크마다 다시 판정한다.** 각 태스크 본문의 `🧪 검증 시나리오` 네 번째 항목이 이것이다.

---

## 규칙 1 — 근거 4항목 없는 후보는 반환하지 않는다

**4항목** = 선정 이유 1줄 · 근거 속성 · 확인 일자 · 확인 주체

### 게이트는 정렬보다 앞이다

```
후보 모집단 → [EvidenceGate] → 적합도 정렬 → 상위 3건
                    ↑ 여기
```

**정렬 뒤에 필터를 두면 후보가 3개 미만으로 떨어지는 경로가 생긴다.** 게이트를 먼저 통과시키면 정렬은 항상 유효 후보만 다룬다.

### 타입으로 강제한다

- `CandidateCardProps`의 `reason`·`evidenceAttributes`·`verifiedAt`·`verifiedBy` 넷을 **모두 non-nullable**로 선언한다. 옵셔널이면 누락이 컴파일을 통과한다.
- `CandidateCardProps`는 **`EvidenceGate`만 생성한다.** 다른 곳에서 조립하지 않는다.

### `STALE`은 제외 사유가 아니다

`verified_at`이 90일을 넘으면 **경고 배지를 붙여 노출**한다. 제외하지 않는다.
제외 사유는 **4항목 중 하나라도 없는 경우뿐**이다.

### 근거 문장 생성이 실패해도 카드는 남는다

AI 스트림이 실패하면 사실 속성 3항목과 **규칙 기반 기본 문구**로 4항목을 채운다.
AI 실패가 카드 소멸로 이어지지 않게 한다 — `근거생략` 상태(§7.3).

> 근거 표기 누락은 **1건 발생 시 즉시 알림**이다 (§6.3).

---

## 규칙 2 — 빈 화면을 반환하지 않는다

**빈 화면을 반환할 수 있는 코드 경로 자체를 없앤다.** 예외 처리가 아니라 정상 경로의 분기로 구현한다.

| 상태 | 화면 처리 | 근거 |
| --- | --- | --- |
| 폴백표시 | 구조화 필터 UI + 전환 고지. **Top-3는 계속 표시** | `REQ-FUNC-009` |
| 근거대기 | 카드 골격과 사실 값 표시, 문장 자리만 로딩 | `REQ-IMPL-015` |
| 근거생략 | 문장 없이 속성·확인 일자만. **카드를 숨기지 않는다** | `REQ-FUNC-010` |
| 유사메뉴대체 | 대체 사실을 문구로 명시 | `REQ-FUNC-007` |
| 제안없음 | 빈 제안 화면 대신 **제안 없는 Top-3로 회귀** | `REQ-FUNC-025` |
| 재시도안내 | 사유와 재시도 수단 제시 | §8.3 규칙 5 |

**`NlConditionParser` → `StructuredFallback` 위임**이 이 규칙의 구현체다. 파싱 실패를 예외로 던지지 않는다.

---

## 규칙 3 — 주관적 판정을 하지 않는다

- 컴포넌트는 **사실 값만 표시**한다. "조용한 편" 같은 평가 문구를 만들지 않는다.
- 매장이 등록한 문구도 **등록 속성을 참조하지 않으면 저장을 거부**한다 (`guardWording`, `REQ-FUNC-021`).
- 판정형 어휘 기준은 `UX-C`에서 확정한다 — 기준이 없으면 `EVD-B`를 착수하지 않는다.

**시스템은 재료만 제공한다.** 판정은 이용자가 한다.

---

## 규칙 4 — 노출 순서를 판매하지 않는다

- **적합도가 1순위 정렬 키다.** 가격은 정렬 키가 **아니다** (`REQ-FUNC-024`).
- 광고·제휴에 따른 순서 조정 코드를 만들지 않는다 (ADR-004).
- 불이행 기록에 따른 **소환 가중치 하향**은 허용된다 — 이건 품질 신호지 판매가 아니다 (`REQ-FUNC-026`).

---

## 필터 판정에서 자주 틀리는 것

**사전에 없는 조건을 하드 필터로 쓰지 않는다.** 미등재 조건을 필터로 쓰면 빈 결과가 늘어 `REQ-NF-010`(빈 결과 ≤ 2%)을 깨뜨린다.
**정렬 가중치로만 반영**해 후보는 유지하고 순위로 표현한다.

---

## 체크리스트

- [ ] 근거 게이트가 정렬 **앞**에 있는가
- [ ] 카드 props 4항목이 non-nullable이고 게이트만 조립하는가
- [ ] `STALE`을 제외하지 않고 경고로 처리했는가
- [ ] 이 경로에서 빈 화면이 나올 수 있는가 — 없다면 왜인지 한 줄로 답할 수 있는가
- [ ] 평가·판정 문구를 생성하지 않았는가
- [ ] 정렬 키에 가격·광고가 섞이지 않았는가
